# U05 静态代码审阅可追溯到版本并讨论

状态：首版已实施，见 [U04–U06交付](../delivery-u04-u06.md)。条件卡真人复核/真实模型质量及完整网页故障矩阵仍未验收；U06正式经审自动判断没有启动。以下原验收合同保留。

**对应目标：** F8静态 + A4

**优先级：** 接续

**Blocked by：** 无

**工程投入情景：** 2–4开发日；不是交付保证，不含外部等待。

## What to build

学生选已保存代码版本和一条静态提示，问原因，再对照修改前后；始终知道代码未执行。

## 选择的实现范围

- 保留assignment/code_hash/previous_id；增加静态规则版本与固定scope，不自动重审历史。
- server只读选中代码范围/行号和静态finding，代码文本不成为指令或执行入口。
- 修改后创建新版本；任何手动轨迹单列为学生提供，不能认作程序输出。

## Acceptance criteria

- [ ] 两版本/行号定位绑定正确；跨owner或代码hash变化拒绝；dirty未保存内容有明确提示。
- [ ] 规则数量减少不自动显示算法正确；有限合法变体与规则漏检回归。
- [ ] 历史没有rule version标legacy，模型建议不改原始review；帮助锁有效且不写独立成绩。

## 回滚与恢复

保留代码/审阅/手动轨迹，只关闭讨论与新规则版本。

## STOP conditions

必须执行代码才能给结论时，降级未判断；不能放开现有AST替代C0。

## 验收与记录

使用母计划§验收合同：先对本切片反例/状态/权限/恢复做针对性测试，再跑适用完整回归；UI变化做桌面/390px、键盘/主题/取消/刷新/空/错误态实际验证。条件项必须有对应真实环境回执；源码、fixture、live、教师审核和学生研究分别记录。实现偏离写母目录implementation-notes.md的Deviations；不是STOP的保守选择可自行完成并记录。
