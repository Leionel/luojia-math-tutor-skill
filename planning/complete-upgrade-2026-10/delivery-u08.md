# U08 账号会话首版（临时库验收）

基线 `8e37b25`。用户授权 U06 后有额度继续；本片实现与验证均在临时库进行，未读取或升级正式学生数据库、未改私有配置。正式库备份/恢复与部署仍 pending。

## 登录与退出

- 注册先验证签发 secret 与有效期（1秒至31天）、准备 v2 token，再在同一 SQLite 事务写用户和登录会话。签发不可用、写入失败不留下半成功账号；并发同名注册只成功一次。请求不接受客户端角色或 sid。
- 保留自定义两段 HMAC Bearer 形式，没有改名 JWT/OIDC。v2 增加随机 sid，服务端表保存 owner/到期/撤销时间；新 HTTP 请求要求存在、未撤销且 token/表到期时间相同的会话。
- 旧 v1 只保留签名解码接口用于历史检查，不能授权 HTTP，请重新登录。角色由当前生效的服务端配置决定，忽略 token 中的旧角色；配置文件仍需正常加载，不宣称编辑文件即自动热更新。
- `/api/auth/logout` 只撤销当前 sid，可幂等；不删除账号、学习记录或其他登录。过期/伪造/失效 sid 返回未授权，不回退 demo。
- 前端只保存身份相符的 v2 登录响应。成功退出后清理本地凭证；网络或未知回执失败时保留登录，明确服务端撤销未确认，并提供重试/仅清除此设备入口。demo 本地退出不调用服务端撤销。
- 身份变化后，学习工作区/Chat 丢弃已挂载旧身份状态；跨标签页同步跳回登录。首页清空并重新读取个人摘要，旧 owner/凭证的迟到结果不展示。用户草稿按 owner 保留，退出不清空全部 localStorage。

## 数据迁移与上线 gate

Migration **7：auth_sessions**，只新增会话表与索引。DDL、迁移版本登记在事务内；失败回滚不删除原账号/消息。原 migrations 的顺序/唯一性回归保留，末版本断言随7更新。

临时库已测试：从保留账号/历史消息的 v6 数据迁移、SQLite backup/恢复到另一临时路径、integrity_check；也注入迁移失败验证回滚。**这些不证明正式库已备份或正式恢复成功。**

正式启用前顺序：停止目标 API 写入→确认实际数据库路径→用 SQLite backup 导出已有账号/会话/学习数据库并保留旧程序→在独立路径恢复、核对历史数量及 integrity_check→同步更新 API/Web→要求旧 token 重新登录→验证新登录/撤销。记录实际备份路径、hash、恢复结果与回滚步骤。路径和正式数据未核实，不提供猜测库名或自动执行命令。当前代码下次初始化对应 Repository 时会应用 migration7，故未经正式备份验收不要启动新版本连接正式库。

## 验证与边界

完整根测试：知识 JSON、API **899**、Web **70**通过；增量 E0 **11合同 / 19实例**通过。Web生产构建（含TypeScript）通过；lint 0错误、10项既有警告。日志 ignored `results/u08-*`，manifest `evaluation/agent_reliability_u08.json`；报告记录源码/hash及 dirty HEAD，不是上线证据。

实际网页使用预先创建的合成账号：登录后读取本人计划；Chat退出后两个标签页都回到登录，输入不展示给下一个身份。仅读取本任务临时库的安全聚合回执：1次登录、1条撤销、账号仍存在，未导出 token/密码。回执 `results/u08-ui/auth-receipt.json`。网络失败/迟到身份变化用前端离线测试验证；没有关闭用户正式服务模拟断网。首页跨身份保护已实现；所有主题、故障矩阵与正式角色名单未做浏览器验证。
