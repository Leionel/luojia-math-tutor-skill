## 为什么先做这些

R1-A/B 的工程回执已经有较多通过数，但内容仍未经真人审核，直连模型9条公开提示也没有经过本应用的路由、工具、引用和 UI。先把“待审核的是什么、跑过的是什么、分母是多少”固定住，才可能在后续对照中知道改进来自数学工具、来源上下文还是教学决策。R2.1 复用 S5 审核协议，R2.2 复用现有 `eval_agent_reliability.py`，没有引入另一个评分框架或新 Agent。CI 漏跑存储测试是实际发现的覆盖差异，统一命令后可由同一测试清单复验。

### R4 先准备的120秒演示脚本

这是准备脚本，不是已录制/已验收视频。使用隔离合成账号，取当前 `/lab` 的内置 Newton 活动；真实模型反馈段须用实际回答，缺模型时留待录，不能用固定文字假装真实推理。

| 时段 | 屏幕操作与要讲清的内容 |
|---|---|
| 0–20秒 | 展示 `f(x)=x³−2x+2, x₀=0`，输入“导数非零所以会收敛”的预测与理由。问题是一次局部计算能否支持收敛判断。 |
| 20–45秒 | 揭示0→1→0，看到已揭示步骤的曲线/切线；分别代入 `f(0)=2,f′(0)=−2,f(1)=1,f′(1)=1`。轨迹提供观察，精确代入提供本题二周期依据。 |
| 45–80秒 | 保存自己的解释，引用到Chat；展示来源run/hash与参考帮助标记。真实Agent反馈应承认正确更新、指出全称推广缺口并追问适用范围；出现误判也如实保留。 |
| 80–105秒 | 修订成“此函数、标准更新和初值0下往复，不能推出任意初值收敛”；返回活动，查看原预测与修订。 |
| 105–120秒 | 刷新恢复记录；解释参考帮助不计独立掌握。若演示参数预览，说明是学生改初值、服务端计算和显式保存，当前并非Agent自主设计实验。 |

配套先掌握三条真实调用链：

1. **学生参与与披露**：`apps/web/components/learning/newton-activity.tsx` → `routes_learning` → `NewtonActivity.predict/reveal/step/explain/revise`。自己解释预测、已揭示步、帮助曝光和修订如何保存。
2. **Agent看到什么与能确认什么**：`TutorOrchestrator.stream_reply` → `resolve_learning_context` / `_saved_newton_claim` → `prompt_builder.build_messages` → Teacher/Guard → 学习metadata。自己解释owner/hash/版本、固定题exact证据及 `verified=False/is_correct=None/mastery_delta=0` 的范围。
3. **受控动作如何落地**：`root_proposal` → `LearningActions.preview` → `run_reference` → `LearningActions.save`。自己解释为什么参数预览不算预测、学生显式保存、幂等和新引用；说明目前缺少Agent选择实验参数的决策证据。

准备完成的标准是：能在实际页面走通并亲自讲清这三条链，有一条正确步骤、一条错误推广和一条unknown边界；录制前没有依赖未验收的功能。R4材料可反过来暴露产品断点，但不改变R2质量Gate。
