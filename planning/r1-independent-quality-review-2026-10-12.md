## 发现

1. **P2，高置信度：B3 不能把本题通用线索写成已定位错因。** `apps/api/app/tutor/learning_workspace.py:36-42` 每题只有一份 condition/method；`:393-407` 只看 `reference_match`。Newton 更新题错选 `2.5` 与 `1.75` 会收到同一“先核对条件：…导数和减号”提示，二分区间题错选 `0.125` 与“无法给界”也共用线索；测试 `apps/api/tests/test_learning_workspace.py:257-271` 只检查统一前缀。不同错项可能来自算术、符号或前提理解，现有单选结果不足以确定原因。**最小修改**：把首层改成明确的“参考选项不符；以下是本题核对线索”，不暗示已归因；若要逐错项反馈，先编写每个错项的可复核解释并做独立二审。**取舍**：中性措辞成本低但个性化较弱；逐错项素材与审核成本增加。
2. **P2，高置信度：B4 会提示本题一种合法的直接残差停止实现。** 固定作业 `apps/api/app/tutor/learning_extensions.py:33-38` 是 `f(x)=x²−2`、`x₀=1`、正根区间 `[1,2]`、根误差目标；`:180-190` 一见 `if abs(fx)<=tol` 直接退出就追加 `algorithm_suspicion`。对标准 Newton 更新 `xₖ₊₁=(xₖ+2/xₖ)/2`，从 `x₀=1` 起各步 `xₖ≥1`；在正根与迭代点之间 `f′(x)=2x≥2`，由中值定理有 `|xₖ−√2|≤|f(xₖ)|/2`，所以直接残差阈值 `tol` 是根误差目标 `tol` 的保守充分条件。现有文案说“不判定代码错误”，因此是**误导风险**，不是已证实的错误判分。`apps/api/tests/test_learning_workspace.py:594-601` 的 `/2` 反例只证明 AST 不触发，未独立证明正确代码族的误报率。**最小修改**：对固定题把文案改为“直接残差阈值可能已足够；请解释迭代范围与导数下界”，并在正确与错误变体上盲审提示是否会让学生误以为正确写法必错。**取舍**：保留追问可促进说明停止依据，但提示更弱、规则覆盖率仍有限；若误导无法收敛，撤回新增规则，保留 U05 静态首版。
3. **P2，高置信度：B5 后端同会话测试不能充当完整质量验收。** `apps/api/tests/test_r1_b5_workspaces.py:14-109` 顺序发送预先构造的引用并使用固定回复；自检交卷后用教材 `reading` 引用，不携带本题答案。`planning/r1-b5-delivery.md` 已披露该边界。**最小修改**：回执继续只称“本地后端同会话工程回归”；若要宣称跨工作区学生体验通过，另用隔离浏览器走 Chat→各工作区→Chat 的真实导航、刷新/身份切换与错误恢复。**取舍**：浏览器验收增加时间，但可发现仅靠 ASGI 测试看不到的导航问题；它仍不能证明教学收益。
4. **P2，高置信度：首页主入口与 B1 已计算的推荐优先级冲突。** `apps/api/app/tutor/learning_workspace.py:94-115` 在自检未交卷时优先返回 `recommendation.kind=assessment_in_progress`；`apps/api/tests/test_learning_workspace.py:442-456` 已构造“待办任务与进行中自检并存”。但 `apps/web/app/page.tsx:52-54,78-82` 先用 `next_task` 决定标题和链接，只有无任务时才显示自检。此状态会把主按钮导向 `/study?task=...` 而非未交卷的 `/assessment`，并可能遇到自检帮助锁。**最小修改**：让首页消费服务端 `recommendation` 的白名单链接与文字，或至少让进行中自检优先于 `next_task`；补同状态前端回归。**取舍**：前者统一策略但需审查服务端链接白名单，后者改动小却可能继续在到期复习/陈旧来源等优先级上分叉。
5. **P2，高置信度：Newton 活动的“防剧透”只绑定当前 run ID，A5 回执措辞过宽。** `planning/r1-a4-a5-delivery.md:13` 写通用实验读取/列表/重放不能在未完成时返回未来轨迹。实际 `apps/api/app/api/routes_learning.py:294-301` 仅在通用 POST 返回的 ID 等于活动 `run_ref.id` 时遮住未来步骤；`apps/api/app/tutor/learning_workspace.py:336-349` 对同 owner、新 `request_id`、同参数会创建另一条完整参考 run，未检查活动 reveal 状态。`apps/api/tests/test_newton_activity.py:120-133` 只覆盖同 ID 的列表/重放。因而学生可在活动只揭示 `x₀` 时于通用 Lab 再运行同题，看到后续轨迹，而 `answer_exposure` 仍记录为未曝光。这是**教学状态与入口一致性**缺口，不是越权读取他人数据；学生本来也可手算或用外部工具，不可能绝对防剧透。**最小修改**：回执和 UI 明示只保证“活动绑定 run 的逐步揭示”；若产品要把内置通用 Lab 的同题运行记为帮助曝光，按规范化参数识别并记录/提示，再做新 request ID 回归。**取舍**：全局拦截等价数学问题成本高且容易误伤正常探索；记录曝光更诚实但需定义同题等价边界。
6. **P2，中高置信度：到期复习可能跨课程版本沿用旧练习证据。** `apps/api/app/tutor/learning_workspace.py:257-264` 保存 review 时没有来源 `graph_revision`；`:102-130` 可在旧任务已 stale 时先推荐到期 review，`:167-198` 用旧 `parent_episode_id` 创建标为当前 revision 的新任务。若旧版本与新版的该单元条件/题目发生实质变化，新任务就把旧 episode 当作现行复习依据。源码路径明确，但尚未构造实际课程变更的隔离复现，也未证实每次 revision 都改变该单元；因此**风险成立，影响条件待验证**。**最小修改**：复习记录绑定来源 revision 或该单元内容 hash，推荐与建计划时先核对，不一致则引导核对来源；若允许跨版本延续，记录该单元内容未变的依据。**取舍**：会使部分旧复习暂停并增加迁移处理，但避免“全图修订即全部失效”的粗暴规则。
