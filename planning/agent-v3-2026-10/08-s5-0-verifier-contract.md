# S5.0：诚实的本步核验与学习资格合同

修订日期：2026-10-07。依据：[独立审阅 R1–R3](07-plan-review.md)。**已实施并完成离线工程验收**，详见[09交付回执](09-delivery-s5-0.md)。以下保留实施前验收合同；新的质量评测/live仍未完成。当前两周只承诺这个切片，工期与人员假设见[日程](04-roadmap.md)。

## 完成的含义

同一个学生请求经过真实路由、受控核验、学习资格检查、消息保存和状态展示：支持的正常题能得到有范围的反馈；不支持的题明确保留未知；系统代算、关键词猜测和参考帮助不会冒充学生作答。安全、能力保持和学习语义必须同时通过，不能以全部 unknown 完成验收。

复用现有 parser/worker 生命周期、VerifyResult、message metadata、Guard 和两处学习写入；无新 Evidence 服务、通用 CAS、数据库迁移或成绩重算。

## 最小正常能力矩阵

以下是实现必须兑现的 development 回归，不能转作封存题。只支持单变量实数 x 与明确列出的操作；变量域、候选和来源必须绑定到原输入。

| 操作 / 输入 | 必须保留的结果 | 学习资格 |
|---|---|---|
| 学生提交 `d(x^2)/dx=2x`；Unicode 表示 `x²` | 规范化为受控树，核对候选为正确；原句和规范化版本可追溯 | 满足政策、候选和范围合同后可形成当前普通单步学习事件 |
| 学生提交 `d(x^2)/dx=x` | 核对候选为错误；可确认的错误类型与关键词猜测分开 | 同上；不得仅凭出现“导数”持久化误区 |
| 单纯请求“帮我检查求导 x**2”，没有学生候选 | 可给参考导数 2*x，说明未核对学生结果；`is_correct=null` | false，mistake/mastery 均不写 |
| 一元多项式等价：`2x=x+x` | 正确保留隐式乘法表示；在声明的实数范围核对 | 仅绑定的学生候选可计入普通估计 |
| `x/x=1` | 只说明共同定义域 x≠0 上等价，保留原式排除点；全域同定义域的命题另行判断 | scope 不覆盖学生原命题时 false；不能以约分结果判全题正确 |
| 明确 x 为实数：`sqrt(x^2)=|x|` / `Abs(x)` | 在实数域核对；缺域时声明可接受的域约定或追问，不能把未确定判错 | 只有明确域及匹配候选才允许 |
| 常见参考求导 `exp(x)` / `e^x` | 有限规范化后计算参考导数，结果范围可见 | 没有学生候选时 false |
| `x**(1/2)` 的普通输入表示 | 仅对精确的有理半次幂做受控 sqrt 表示转换；明确原式实数定义域及求导范围；原点求导不能被确认 | 只有操作和范围覆盖候选时允许；不扩成任意分数/变量指数 |

首批必保留操作是**有界一元等价和导数候选核对**，不是仅实现参考求导。函数集合由此矩阵最小化确定；Abs 等构造若新增，只开放固定受控 operation，不自动扩大所有 native tools 权限。普通不定积分候选、2×2 行列式、未定式分类列入能力清单：能安全保留就逐项验收，否则明确暂时降级及恢复条件；不得继承旧 unsafe 实现。积分、洛必达、复杂定义域都不是首批必须建完整 checker 的理由。

## 安全构造与调度

1. 盘点全部学生输入→`parse_expr`、字符串 `sympify`/`sp.diff` 的可达路径，按 operation 迁移。规范化是有限词法/AST 转换，不能 eval、执行学生/模型代码，不能用黑名单代替白名单。
2. AST 构造前后保留原式摘要、候选、域与简单排除条件。原式约分、sqrt 或特殊函数条件无法可靠保持时，结果 unknown，不尝试任意 CAS 求域。
3. 复用固定子进程的拥有、取消、超时、输出回收；每个请求的次数/字节预算明确，不增加进程池或新注册框架。
4. **检索预算与本步核验预算分开。** 现有 collector 为350ms，固定 worker 冷启动本机已观测约1.3–1.4秒；直接复用同一 wait 不满足矩阵。核验预算初始拟定最多5秒，实施时用正常输入实测校准；始终取本步配置和总请求剩余期限的较小值。5秒是配置提案，不是性能验收结果；不能扩大检索等待或取消总请求保护。
5. 外层取消/帮助边界变化必须终止并回收拥有的 worker；timeout 只产生明确未知和原因，不再调用旧 parser 或恢复模型 Python。

## 判定与两个写入入口

内部需分别表达执行状态、数学判定和学习资格；优先映射已有字段，只新增无法表达的版本化 metadata，不要求学生理解五种 Evidence 标签。

| 维度 | 必须区分 |
|---|---|
| execution | 未请求、完成、语法拒绝、超时、失败；工具执行完成不产生学生正确性 |
| verdict | 指定输入/域/scope 内正确、错误、unknown；unknown 映射 `is_correct=null` |
| origin / binding | 学生原始候选、系统参考计算、模型意见、heuristic、可信参考轨迹；原输入/候选 hash 和 checker 版本可核对 |
| eligible_learning_evidence | server 根据候选存在、绑定一致、可判定结论、范围覆盖和当前帮助/任务政策决定；LLM不能写 true |

必须分别在 `add_mistake_event` 与 `upsert_mastery` 的消费入口检查资格；仅将 VerifyResult 改 unknown 不足以阻止现有 mistake 写入。heuristic 留作待核对教学线索，不进持久错误标签。无候选代算、未知、scope不匹配及 LearningContext/reference_help 都不得冒充学生检查事件。

核对普通学生候选时，继续使用现有 hint/帮助规则估计；受助修订不变成独立 probe 成绩。本切片不改变独立 probe、ack、正式分数和参考轨迹不计掌握的合同，不重做全局消息/学习事务架构。

## 历史与界面

- 新结果的 SSE、持久 metadata、刷新状态使用同一投影；旧客户端兼容字段不能把 unknown 重新显示为正确。
- 可见状态至少区别“未请求核验”“核验未确定及原因”“已核对候选及范围”“只做参考计算”；超时不是未发生检查。
- 无新版证据字段的旧消息展示 legacy/范围未记录，保留原正文；再次送入 history 时加有限的历史来源提示，不能把旧“通过”当本轮确定事实。
- 历史 mastery/mistake 缺事件级 checker 版本和可逆 delta，只能说明来源不明或列候选影响范围。没有证据不得精确归因、自动重算或删除历史记录。

## 验证与验收

先冻结上述矩阵，再实现。真实 compiled graph 与隔离临时 SQLite 验证候选绑定、代算、正确“互斥≠独立”、unknown仍带mistake线索等路径；同时覆盖正常/错误候选、缺域、旧消息、帮助锁定、取消/超时和刷新状态。固定模型响应只验证工程合同。

通过条件：所有旧可达 unsafe 字符串入口封闭；矩阵的正常题不能全部 unknown；代算/heuristic/unknown/reference_help 在两处 sink 均零不合法写入；checker结果与可见状态一致；owner、原子交付和独立 probe 合同不回退。仅语法拒绝通过或仅 worker 单测通过不构成整片完成。

实施时运行 `npm.cmd test`、E0 CLI；后端 pytest 从 `apps/api` 运行并保留离线门控。若改 UI，运行 typecheck/lint，停 dev 后再构建，并做隔离桌面/手机状态核对。本轮尚未执行这些修复后的验收。

STOP：正常承诺子集被350ms取消、仍有unsafe回退、代算/unknown仍计入学习、权限/帮助/终态回归失败、旧来源被当新证据。遇到这些情况先收敛切片，不能增加新模块掩盖失败。安全止血可先交付为明确降级版本，但必须标为“止血完成、能力保持待验”，不得冒称整个 S5.0 完成。
