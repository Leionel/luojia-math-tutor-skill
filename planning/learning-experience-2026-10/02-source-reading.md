# F2：教材伴读与条件卡

> 状态：待实施；目标窗口2026/10/02准备、10/15–11/11首版；估算4–6开发日。
> 依赖可访问、来源与版本明确的求根小节；不依赖完整F1或F3。

## 1. 首个可用流程

从一条教材引用打开原文小节 → 选择一段定理或公式 → 在当前页面查看符号/条件解释 → 完成一道条件辨析题 → 保存带原文引用的笔记 → 回到原会话。

首版阅读已解析的Markdown/公式，不先做完整PDF批注编辑器。已确认PDF页码时展示页码；只有段落定位时显示小节和段落。两者都缺失时显示真实摘录并标注无法精确定位，不伪造页码。

## 2. 内容模型与教学动作

首版人工审核约6–10张求根条件卡，覆盖：

- 二分法的连续性与端点变号、区间不变量、区间误差界；
- 不动点映射入区间与压缩条件、不同迭代格式的差异；
- Newton导数与初值、局部收敛条件、近零导数/循环/重根；
- 残差、步长与根误差的区别。卡片数量为内容准备目标，不作为教学质量指标。

条件卡含：已审unit_id、graph_revision、原文quote与定位、条件列表、适用/不适用的例子、一道最小辨析题、教师确认的参考答案与允许解释。训练题答案先隐藏，学生作答后按教学策略可显示解析；研究测评题的答案由独立接口边界管理。

动作分工：符号解释/换说法可以由LLM产生，明确是模型解释；原文引述、条件列表、题目参考与数值状态来自对应数据/工具，不能让模型追加“原文已说”的条件。资料不足则补充为“教学补充，尚未由本段来源支持”。

示例：二分法条件卡提供函数在区间内连续、端点异号的原文条件；学生判断`1/x`在`[-1,1]`是否可直接据变号断言有根。结论依据缺失连续性及定义域，不把采样图当数学证明。

## 3. 来源与权限契约

当前Repository有按user_id获取文档/原始Markdown的能力，但课程共享材料访问应单独确认，不能直接把任意私有document_id暴露给课程学生。

首版优先沿用已确认的私有文档owner访问；课程共享材料需要教师发布的最小授权映射，明确course/document/version和允许读者范围。没有授权记录的材料不进入共享阅读。

拟定`SourceAnchor`：document_id、content_hash、section_id、段落起止或受控span、quote_hash、可选page_start/page_end、course_id、graph_revision。定位到哈希对应的原文；文档改版后标记旧引用过期，不静默跳到别段。

不从重叠chunks重新拼接“原始教材”。当前Repository的全文Markdown优先；长文只按小节分段加载。不假设已有跨页准确布局，页码精度单独验收。

## 4. 界面与状态

桌面原文与辅导并列；手机先原文，解释在选段附近展开。保存笔记在当前上下文完成，返回保留阅读位置、原会话和未提交回答。

| 状态 | 行为 |
| --- | --- |
| 缺材料 | 提供上传自己材料/进入现有聊天的入口；不虚构原文 |
| 无访问权限 | 不返回内容片段；说明需要自己上传或课程授权 |
| 有摘录无准确位置 | 展示摘录和已知来源；不承诺精确跳转 |
| 文档更新/引用失效 | 标记原版本，允许查看已授权旧快照或请求新版本映射 |
| 解释生成失败/超时 | 原文仍可读；保留选择与问题，允许重试 |
| 辨析题评分不确定 | 记录待复核，不加独立数值成功；可请教师核对 |
| 笔记保存失败 | 保留全文与引用，恢复时同幂等键重试 |
| 长公式/选段/窄屏 | 公式局部滚动，限制选段范围，核心动作键盘可达 |

## 5. 拟定接口、复用与修改位置

| 拟定接口 | 行为与权限 |
| --- | --- |
| GET `/api/reading/documents/{id}/sections` | owner/课程授权检查后返回目录与版本 |
| GET `/api/reading/documents/{id}/sections/{section_id}` | 返回已授权小节与稳定anchor；不因知道ID绕过权限 |
| POST `/api/reading/explain` | 受控anchor+学生问题；服务端取原文，不相信前端伪造quote |
| GET `/api/reading/units/{unit_id}/condition-card` | 返回已审卡片的公开部分、来源与版本 |
| POST `/api/reading/condition-attempts` | 保存辨析作答；评分/帮助分类来自服务端 |

笔记优先扩展既有`routes_notes.py`/Repository保存接口，明确存source anchor与note内容，不另建笔记产品。需要原始段落索引时使用已有文档全文与标准库解析，只添加稳定section index；不先引入新的PDF/RAG服务。

复用：`api/routes_notes.py`、`memory/repository.py`、`knowledge/schema.py`、`evidence_builder.py`、`apps/web/components/{source-span-card.tsx,notebook-chat.tsx,latex-renderer.tsx}`、`apps/web/lib/api.ts`。
拟新增：`api/routes_reading.py`、`knowledge/source_anchors.py`、`apps/web/app/reading/page.tsx`和条件卡组件；读私有文档走Repository，读正式条件卡走CourseStore，分别检查访问边界。

选段解释调用沿现有模型配置与不可信上下文策略；一次请求限定一个小节/选段，保留来源范围、延迟与费用。首版无模型key时原文和已审条件卡照常可用，模型解释入口说明不可用。

## 6. 两个执行任务

| 任务 | 首个完整行为 | 验收 |
| --- | --- | --- |
| R1，2–3日 | 引用→原文小节→定位→返回原会话 | owner/课程授权、全文来源、过期anchor、手机/键盘、返回位置；不要求另一功能先上线 |
| R2，2–3日 | 条件卡→辨析作答→解释→带引用笔记 | 经审参考/合法解释、答案适时披露、模型失败降级、保存幂等与恢复；依赖R1 |

## 7. 验收与停止条件

新增回归：不存在文档、跨用户、共享授权撤销、伪造anchor/quote、同摘录多个位置、文档版本更新、无页码、重叠chunks、公式截断、模型拒绝/超时、答案键访问、笔记保存失败。

未来定向文件建议`apps/api/tests/test_source_reading.py`及必要anchor工具测试；完整命令见总规划§8.2。真实模型验收由教师检查有限样例：解释是否忠于选段、条件是否完整、补充是否标明、合法作答是否误判。只做离线测试不能声称模型解释质量通过。

原文身份/许可或课程授权无法确认时停共享材料写入，可继续私有授权fixture。模型解释可关闭，阅读仍可用；不删除既有笔记，不改教材gold迎合解释器。文字讲回F5可复用R2条件，不需要另建通用问答框架。
