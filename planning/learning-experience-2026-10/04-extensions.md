# F4–F8：后续功能的具体任务

> 状态：规划；纳入同一六个月候选功能路线。每项先做薄版本；教师、字幕和隔离依赖不能以代码完成代替。
> 时间和产能见[总规划](README.md)§5。新API与文件名均为拟定；本轮未实现。

## F4：章节诊断与考前练习

### 首版体验与范围

选择求根章节 → 做约5–8道经审诊断题 → 交卷 → 按条件理解、更新公式、停止依据反馈 → 生成下一项训练任务。题数为首版任务设计，不称全面掌握度测量。考试日期可生成复习安排，不保证得分或学完全部内容。

首版至少包括条件辨析、轨迹判断、一次更新与停止准则；教师确认答案、允许替代路径和评分规范。练习与正式研究测验分task_pool、版本与访问权限，不能同一套换个参数便称独立泛化。

### 行为和数据契约

- 服务端生成assessment_id、题目快照、任务类型和版本，固定题目与首次有效作答；学生不能修改答案键、独立模式或开始时间。
- 状态：not_started/in_progress/submitted/scoring/completed/partial/expired；刷新恢复；网络失败不清空答案；弃测与超时不伪造成零分学习失败。
- 独立模式下所有相关辅导请求由服务器检查任务上下文；F2答案、F3参考轨迹、Case/题目API也要遵守边界，不能只隐藏前端按钮。
- 普通练习提交后可解释；研究测验何时放解析由冻结协议决定。先填“未确认/待人工评分”，不能把LLM文本评价直接变数值正确率。
- 拟定接口：POST `/api/assessments`、POST `/api/assessments/{id}/answers`、POST `/api/assessments/{id}/submit`、GET `/api/assessments/{id}`；owner与题目公开/私有DTO分开。

### 任务A1与验收

A1先完成一份固定求根小测全流程，预计2–3日；加上F5文字讲回，首版工作包合计3–5日。更丰富考前组合可再用1–2日，须从缓冲或实际释放的产能中安排，不包含在首版估算，也不重复计入研究测验工程。复用RootEpisodeService、prompt_policy、已审条件卡与Exercise库；拟新增`api/routes_assessments.py`及`app/assessment/`中最少必要服务、前端assessment页。

验收：重复提交、改题/改模式、跨用户、刷新/断线、并行标签、教师题版本更新、提交前答案泄露、合法替代解、部分人工评分、练习池与独立集隔离。完整回归见总规划§8.2。

没有经审gold则只做无成绩原型；来源/答案边界失败停独立测评，不关闭普通教学。研究测验不得在收数中途修题/改评分。

## F5：讲给助教听

### 首版体验与任务E1

从一张条件卡点击“我来解释” → 学生用文字说明为何可用、为何停止或如何选方法 → 助教引用学生原话指出尚未覆盖的条件并追问 → 学生补充 → 保存带来源的解释记录。

先文字版，复用现有聊天与条件卡，不新建语音聊天系统。预计1–2日，计入F4+F5总工作包；阻塞R2的已审条件。拟在现有TutorWorkflow/prompt_policy增加teach_back任务上下文，界面优先当前条件卡内展开。

结果至少区分：条件覆盖有依据、可能遗漏需追问、无法判断。评分依据需包含条件ID、学生原句与来源；LLM只能给模型评审意见，不能因此增加独立数值成功。合理不同措辞/次序接受，不用逐字匹配当理解证明。

### 验收与扩展

用教师确认的解释样例覆盖完整解释、关键条件遗漏、合法替代说法、自相矛盾、回答与条件无关、模型超时、提示已暴露、保存失败。学生看到可修改反馈而非永久“错误标签”。

模型评价质量待教师核对；未通过时保留“自我讲回＋条件对照”，关闭自动评分。语音转写仅在文字版稳定后评估；转写有编辑确认，不直接以识别文本计算成绩。

## F6：视频伴学

### 首版体验与任务V1

从现有B站推荐打开一段有来源字幕的视频 → 选时间点或字幕句 → 提问“这一步用了什么条件” → 回答回引字幕与教材 → 保存疑问 → 完成一题经审检验。

首版先用一段获准使用的视频及SRT/VTT字幕打通，预计4–6日。没有可用字幕就保留普通推荐，不从视频标题/简介编造时间点内容。平台字幕访问方式未确认前，不开发未经证实的批量抓取方案。

### 来源、状态与数据

`VideoSource`：provider、video_id、可访问URL、字幕来源/许可记录、caption_hash/version、语言；`CaptionSpan`：start/end、原文；问题绑定span和教材anchor。首次问答使用限定时间窗及相关教材，不把整部视频无界注入模型。

播放器位置、字幕选择和回答来源分开保存。字幕不保证说法正确，模型解释与教材条件核对分开。没有字幕/私有视频/外链不可播放/字幕不同步/视频下架/模型超时都给恢复路径；可继续读字幕或回到教材。

拟增`api/routes_video_learning.py`、字幕解析/索引小模块、视频伴学页；复用routes_resources和现有播放器/笔记。URL/字幕等走现有不可信输入策略；新增字幕导入校验格式、文件大小与时间序列。

### 验收与进入门槛

至少核对三处真实时间点、字幕哈希变化、连续/断句/重叠时间、跨用户保存、视频关闭后返回位置、移动端、无字幕与超时。答案必须回到真实字幕span；仅检索到字幕不等于已经核验讲解正确。

V1通过后扩若干求根教学视频，逐条记录来源；不增加自动抓取所有课程的承诺。字幕无法取得或使用范围不明则停对应导入，用已授权fixture继续。

## F7：教师诊断简报

### 首版体验与任务T1

教师选择已授权试用名单和时间窗 → 查看高频错误、帮助使用、独立probe、未知结果 → 打开一个episode核对输入、诊断、来源和修订 → 标注需要人工复核 → 导出脱敏简报。

预计2–3日，优先服务M4/M5审阅，不另做学校管理/班级运营平台。列表只聚合真实参与范围；教师角色不能自动读取任意学生文档、聊天或上传文件。首版可用明确课程/试用名单授权，未有名单则用合成fixture。

涉及真实学生数据时必须启用并验收实际认证，不能依赖AUTH_REQUIRED=false的演示兼容路径放行。撤销授权后停止读取；原始数据保留/删除按已告知的使用约定处理。

### 聚合与接口

分母明确：有有效尝试的人/任务、已核对结果、实际展示帮助、受助成功、首次独立成功、unknown。没有数据显示“未观察”，不置零或默认50%；禁止仅以BKT估计输出班级排名。

复用CourseStore事件与episode、auth角色；拟定GET `/api/teacher/study-summary`与GET `/api/teacher/episodes/{id}`，附服务端名单范围检查。人工复核标注单独存审阅记录，不覆盖原始诊断或研究gold；真实内容更正走正式版本流程。

### 验收与扩展

T1覆盖未授权教师、范围外学生、两课程隔离、撤销名单、重复事件、unknown分母、原始证据回查、导出敏感字段过滤、小样本不做过度推断。正式数据使用范围未明确时只做fixture演示。

后续可增加教师布置已审任务、到期查看与分组建议；不自动给学生发消息，不把模型分组建议变成永久能力标签。

## F8：数值代码调试作业

### 首版范围与C0/C1

仅限定Python求根作业：学生提交一个约定函数 → 隔离运行预设公开/隐藏数值检查 → 返回更新公式、停止条件、定义域/边界等有依据反馈 → 学生修改 → 比较前后结果。隐藏测试具体答案不暴露；允许人工复核合法替代实现。

预计7–11日：C0约3–5日证明一个隔离执行路径，C1约4–6日完成一份作业到反馈的流程。现有code_executor禁止循环/函数定义，不能为了这个功能直接放开AST并宣称安全。环境可用性尚未核对；没有隔离条件时仍可提供静态代码审阅与学生提交轨迹。

### C0不可省略的能力证明

选择已实际可用的隔离运行设施，先用临时作业验证：网络关闭；无宿主数据/密钥可读；仅临时工作目录可写；CPU/内存/时间/输出/进程数限制；超时后子进程全部终止；不同用户不共享工作区；作业结束清理临时文件。AST检查只是输入规则，不是操作系统隔离。

上限在C0实测后固定版本。nbgrader是作业/评分参考，不等于沙箱；首版无需整套Notebook平台或多语言系统。若必须新增依赖，先记录现有设施不能满足的具体限制与官方能力证据，再实现。

### C1契约与状态

作业模板由教师确认函数签名、数学目标、允许库、输入/输出、容差、公开检查与隐藏检查。单纯测试通过不证明一般数学定理或学习收益。

`CodeSubmission`绑定owner、assignment/version、源代码摘要/受控内容、runner/image version、资源预算、公开检查结果、私有参考、反馈与帮助记录。状态queued/running/passed/failed/inconclusive/timeout/cancelled；运行完成与数学目标满足分开。

拟新增独立runner适配与作业服务，不塞入tutor/graph.py主流程同步执行；前端展示排队、取消、超时与重新提交，保留代码。题目/测试脚本为可信教师内容，学生文件名/代码/输出作为不可信数据。

### 验收与进入门槛

C0先通过死循环、资源耗尽、联网、读宿主、逃逸导入、派生进程、超量输出、并发用户与取消清理验证；C1再核对正确算法、更新错误、过早停止、合法变体、容差边缘、隐藏答案泄露、模型意见与测试证据区分。

没有C0回执不得开启任意代码运行。C1通过后最多扩大一个求根作业族；NumPy/Notebook、其他语言与跨章调试单独评估。新增入口关闭不删除提交；运行环境不可用时显示不可运行，不伪造执行结果。
