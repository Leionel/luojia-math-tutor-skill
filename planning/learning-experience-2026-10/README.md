## 1. 产品目标与首个完整体验

面向正在学习《数值分析》的大学生，先覆盖二分法、不动点迭代和 Newton。学生进入助教后能知道今天练什么，在教材原文中理解条件，通过数值实验发现错误，并完成一次有证据的修订和独立检验。教师能核对诊断来源，研究能区分受助表现与独立表现。

首个可演示流程：选择“今天15分钟” → 打开一项 Newton 条件任务 → 阅读来源与条件卡 → 先预测初值的影响 → 运行受控实验 → 提交自己的迭代过程 → 查看定位反馈 → 修改并重验 → 完成不同函数的独立题 → 得到下次复习日期。

核心价值判据：是否减少不知道从何开始、只看讲解不作答、反复犯同类错误的情况。页面点击量、聊天轮数、BKT 估计上涨和满意度不能单独证明学会。

## 7. 数据与能力边界

1. 课程、求根episode与过程事件复用CourseStore；会话、文档与笔记复用Repository。新增任务/复习状态优先归CourseStore；不做跨两个SQLite库的伪原子事务。
2. 建议通过课程事件幂等消费更新任务/复习。事件已经提交但派生状态没更新时，可以安全重放补齐；同一事件只能推进一次。双库读取权限先分别验证。
3. `attempt`和阅读/实验操作是观察，不直接视为成功。独立数值表现只从已验收的server verifier和帮助暴露上下文产生；学生不能上传`is_independent=true`领取成绩。
4. 自动实验轨迹、来源条件讲解和讲回反馈算帮助。独立测评入口关闭这些帮助，答案只在适当提交后返回。普通教学继续服从现有direct/scaffolded策略，不把研究限制施加到所有聊天。
5. 保留task、episode、attempt、source、graph、Oracle、policy/model版本。课程更新后旧任务标成版本过期，旧episode按旧版本回查。
6. 文本/公式/字幕/代码都作为不可信输入。复用既有表达式parser、sanitizer与静态预览；实验交互用应用内控件，不执行模型生成的任意JS。

| 情况 | 处理与继续路径 |

| 诊断为inconclusive/tool_error | 保留输入、补条件或重试；不推进成功/复习升级 |
| 迁移失败或派生状态重复 | 临时库注入故障；正式库backup与integrity_check通过后才迁移；可重放恢复派生状态 |
| 一次实验自动运行被算作独立成功 | 停成绩接入；修正帮助/来源分类；历史受影响记录按版本受控重算 |
| 教师或学生未落实 | 继续工程/数学验收；延期对应教师gold/真人阶段；不补造学习数据 |
| 视频没有字幕或无法对齐 | 降级普通视频推荐/用户授权上传字幕；不生成声称来自视频的讲解 |
| 代码隔离无法证明限制有效 | F8仅静态审阅/轨迹输入；保留旧执行器限制；停止任意代码运行 |
| 正式实验已冻结 | 候选开发与实验运行隔离；不为赶功能改变主实验条件 |

功能先限定本地开发/授权试用，提供关闭新增入口的能力并保留旧聊天路径；具体配置复用已有模式，只有确实需要独立控制时才新增flag。回退代码不得删新表或覆盖已存原始事件；派生数据可重建，历史输入按数据使用约定保留/删除。
