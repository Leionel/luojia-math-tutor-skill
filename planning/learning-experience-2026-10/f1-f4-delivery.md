# F1–F4 首版交付回执

日期：2026-10-02；时区：Asia/Hong_Kong。用户授权“先开干 f1-f4”，并补充“自检通过后可以升级”。本轮已实现并本地验收四个功能的首版，不将原规划中全部后续扩展写成已完成。

## 可以直接使用的功能

| 功能 | 入口 | 本轮实现 |
| --- | --- | --- |
| F1 今日学习与复习 | `/study` | 15/30 分钟计划，最多三项；到期复习、失败修订、条件阅读、受控 Newton 练习；反馈确认后保存结果；完成练习后发新题独立 probe；复习日期与阶段；任务链接及输入恢复 |
| F2 教材伴读 | `/reading` | 四个求根知识单元、公式、条件卡、辨析；选择自己上传的原文及章节；原文字符范围和内容哈希；选段提问与回引；问题草稿、来源笔记、阅读位置恢复 |
| F3 求根实验 | `/lab` | Newton、二分、不动点三种参考运行；先预测再运行；初值/区间/阈值/目标/迭代上限；轨迹表、迭代图、历史同目标对照；回到个人练习 |
| F4 章节诊断 | `/assessment` | 固定六题、首次有效作答保存；交卷前不返回答案键；刷新继续；交卷后参考计分、解析及薄弱知识点；后续计划安排条件回顾；弃测保留记录且不计分 |

首页/聊天顶部新增“今日学习”入口，四个页面共享导航与主题。沿用水墨语义色，不另建 UI 色板。

## 学习记录和数学边界

- 阅读为 `read_complete`；系统实验为 `reference_help`；模型解释为 `model_explanation`，未作数学验证。它们不直接增加独立成功或复习阶段。
- 练习沿用 RootEpisodeService / root-oracle-v1：学生提交自己的受控轨迹；服务端固定方程、初值、误差目标；反馈实际确认后才消费结果事件。普通完成、受助完成、独立 probe、失败与未知分别保存。
- 复习策略版本 `review-v1`，间隔 1/3/7/14 天；初始 stage=-1，首次独立成功到 0；后续不同每日学习 session 才可升级，同一天反复做新题不会连续升级。失败回到 -1，受助成功不升级，未知不改调度；重复反馈不覆盖较新的复习父任务。
- 失败任务到期时先安排修订，成功并确认后才能发新题，避免出现“先失败、到期却被要求直接开独立题”的死路。
- 发 probe 时排除已有实验暴露的函数，包括常见等价二次式。此时表达式采样只用于保守排除，不能用作数学正确性证明。独立 probe 首次提交未确认期间，伴读解释与新参考实验由服务端阻止。
- 参考 runner 不执行学生/模型程序；复用受控 AST，最多 80 节点、20 层求值深度、整数幂 -16…16、100 次迭代和有限数值预算。二分采用区间半宽停机；Newton/不动点须另有可核对的误差界才能确认根误差。这里不是通用代码沙箱，也没有另行宣称硬实时 2 秒隔离。
- F4 是 `chapter_diagnostic_training`，答案键为开发版、服务端题目快照；参考分不写入独立学习成绩。六题的数值更新、区间误差和条件答案经过离线自检，按照用户授权升级计分与复习建议；未升级为冻结的教师 gold 或研究测验。

## 存储、接口与恢复

新增 CourseStore 表 `learning_records`：主键 `(owner_id, course_id, kind, record_id)`；计划、任务、复习、实验、伴读笔记/解释与测评使用不同 kind。SQLite 和内存事务都支持回滚，状态更新与事件去重在课程库同事务中。

运行时 `get_course_service` 优先采用 `COURSE_STORE_PATH`；没有显式设置且 `DATABASE_URL` 是文件 SQLite 时，使用同一路径追加 `.course.db` 的课程库。显式 `CourseService(store=CourseStore(None))` 仍可用于隔离测试。非文件 SQLite/内存配置时页面明确提示重启不保存。测试环境沿用临时 DATABASE_URL 与离线密钥门控，并在退出前关闭缓存课程连接。

会话仍由 Repository 管理，原文仍从用户自己的 documents.markdown 读取；不把重叠检索 chunks 拼接成教材。课程摘录明确标“知识包摘录，非教材原页”，无真实页码就不编造。笔记引用由服务器从来源取出，不采信客户端 quote。内容哈希不匹配拒绝保存或解释。

创建会话和课程任务跨两个 SQLite 库，不承诺原子性：成功绑定后重试复用；绑定前失败可能留下未使用的空会话，但不会产生学习成功事件。当前没有补偿清理后台。

API 集中在 `api/routes_learning.py`：`/api/study/*`、`/api/reading/*`、`/api/root-lab/*`、`/api/assessments/*`。owner 仅来自服务端 Principal，不接受客户端 user_id/is_success/mode/答案键；跨用户记录返回 404。demo 模式共用演示身份，不能作为生产认证证据。

浏览器草稿按登录身份和任务/来源分开，网络重试复用请求 ID；任务参数改变后才生成新 ID。模型调用最长等待 20 秒，失败不缓存为成功解释，输入仍保留。真实模型文字按现有 MathMarkdown/LatexRenderer 渲染。

## 相对规划的取舍与后续

1. 四项共用 LearningWorkspace 和一个路由模块，避免首版拆出多套状态服务；课程图、案例、RootEpisodeService 与 Repository 保持职责。
2. F1 先用固定可验证 Newton 练习和现有开发 probe 池；日历式 session 是首版复习去重单位。没有完成教师扩题、FSRS、通用题库计划，也没有自动替换已开始的旧课程版本任务。
3. F2 先做四张开发条件卡和原文选段；原文段落是真实字符范围，课程摘录不冒充教材授权原页。真实模型解释质量、材料授权与教师审阅待验收；没有完整 PDF 页内标注。
4. F3 比较同函数、同目标、同阈值的历史轨迹，图为迭代值随 k 的变化；没有将曲线当成证明、没有完整通用学生代码调试。
5. F4 只做章节练习诊断，保留答案版本/首次有效选择。没有实现研究测验独立模式、无 AI 监考、人工评分或研究用题池隔离；相关接口不得拿这组练习成绩当正式收数。
6. 未运行远端 CI、真实模型或教师/学生试用；未改冻结 seed/gold/研究清单。F5–F8 保留在原规划中。

本轮未统计人工核对工时，不能从一次 AI 编码会话换算为开发日产能。后续应先用实际材料检查伴读质量，再扩经审题库、重新规划旧任务恢复和研究测验协议。

## 预览与运行说明

本轮保留 `http://localhost:3000/study` 的生产预览，以及本地8000 API。两者使用 `results/f1-f4-ui.db` / `results/f1-f4-ui-course.db` 的隔离演示数据；API设置LUOJIA_NO_DOTENV=1，不加载真实模型密钥。因此预览内AI解释走诚实的无模型降级。正常 `npm.cmd run dev:api` 会按原.env配置启动，显式COURSE_STORE_PATH优先。预览不是部署。
