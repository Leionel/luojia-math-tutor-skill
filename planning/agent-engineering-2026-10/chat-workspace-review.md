## 1. 判断：意见抓住了主要产品缺口

采纳“聊天作为统一交互入口，工作区负责复杂操作”的方向。现有功能主要能各自完成任务，但当前实验、今日任务、教材选区和代码版本不能统一绑定到聊天；用户切换页面时要自己重新解释。这比多做一层通用 Registry 更直接影响体验，也更适合先形成可演示的 AI 应用成果。

此前 [Runtime 日程](runtime-review-schedule.md) 先做独立数值工具，顺序需调整：**A4.1 可信当前任务 → A6.1 最小业务动作与卡片 / A4.2 内嵌聊天 → A6.2 计算工具与旧 Python 路径退役 → A7 计量 → A5 评测**。工具权限、预算与证据从首个动作就具备，通用化留待真实复用；不建立并行的 LearningAction / ToolSpec 注册体系。

这个判断不表示应删掉学习页面，也不表示模型成为学习状态的权威。数值播放、教材阅读、代码编辑、作答确认继续在各自工作区；聊天解释、引导和串联它们。F4 章节自检仍是开发参考题训练，`independent_success=false`，不能改名包装成研究独立测验。

## 3. 本轮已修的具体不一致

修复前：新数值实验阻止自检/probe 期间参考帮助，普通聊天/伴读共享的帮助检查只管 probe；求根实验的新运行只检查 probe，并在检查前返回缓存，历史两个 GET 也仅检查 owner。回归新增检查实际得到 **6 失败 / 1 通过**，确认缺口并非仅产品意见。

本轮采用已有授权“可以改的直接改”，只做局部保护修复：

- 共享 `assert_reference_help_allowed` 增加 owner-scoped 的进行中章节自检检查；现有聊天、相似题、生成笔记及 F5/F8 调用共享检查的入口随之保护。
- 求根新运行在缓存复用之前检查；历史读取由 `LearningWorkspace.lab_run/lab_runs` 检查后提供给 API；伴读选区解释使用同一边界。
- 交卷或结束自检后恢复参考帮助；另一个用户不受影响；未确认的 probe 仍保护，合法的 probe 提交在没有进行中自检时仍可核对。
- 不改变题目、分数、首次作答、掌握度、独立成功规则或数据库结构；没有增加内嵌聊天或业务动作功能。

## 4. 首批只打通一个有价值的闭环

第一条路径选成熟的 Newton：**已保存的实验 → 当前页问小珞 → 引用真实轨迹解释 → 参数建议/用户编辑 → 明确触发预览 → 结果卡片 → 用户保存参考实验 → 同页更新**。先解决“为什么这里振荡”和“换个初值”的连续性，暂不把今日任务、教材、讲回、代码与 probe 全部放进同一批。

随后将已有今日任务的 session/episode、教材来源和讲回记录串到该链上；它们是任务关联，不将现有 root episode 重定义为包括所有功能的通用 workflow。开始 probe 后侧栏显示帮助锁定和返回当前作答入口；提交/确认仍走已有受控服务，Agent 不生成答案替学生交卷。

### 最小数据合同

- **LearningContextRef → LearningTaskSnapshot**：客户端给类型、记录 ID、期望版本/哈希和有限选择（例如第几步）。服务端读 owner 记录、真实轨迹和实时帮助状态；`page` 只作 UI 提示，不是授权依据。一个主引用加有限附属来源，避免十几个互相矛盾的 nullable ID。根实验已有 input_hash/runner_version/graph_revision，不能假装它已有 numerical-lab 的 source_hash 字段。
- **LearningAction**：作为 A6 工具合同中的业务操作分类；复用 read_lab_run、preview_root_lab、save_reference_lab 等固定服务映射。READ/WRITE 与“是否暴露帮助”分开；所有动作重验 owner、当前帮助等级、版本和预算。
- **TutorArtifact / ActionProposal**：先只有实验结果/参数建议两类卡片。服务器根据验证过的记录和枚举组装；卡片关联 run/message/artifact/action ID，带有限参数、证据范围、状态和过期规则。首版不要求模型原生 tool calling，也不把服务器组装卡片宣传为已实现模型自主工具选择。
- **Embedded Tutor**：提取共享的会话/流式控制与消息渲染，桌面侧栏、手机抽屉。不能把带全页 Header/Sidebar 的 TutorChat 直接塞进 LearningShell；NotebookChat 尚未有与主聊天一致的 run 回执显示/卸载取消处理，也需按同一合同接入。

### 交互和权限规则

只读 hydrate 可在意图判定前提供必要材料，必须 owner/probe 检查且无学习写入；A0“澄清前不写学习评估”不后退。引入 snapshot 时标记 reference_help，参考轨迹不能被当作学生提交或已掌握证据。参数建议不能替学生填写“我的预测”。

预览没有正式实验记录也会暴露帮助，因此仍要受帮助门槛/预算约束，并记录最少必要的帮助曝光事件；规范化后的函数/任务身份须被现有probe选题与帮助预算读取，未保存的预览也不能被当作未见题。引用系统轨迹不增加学生attempt/BKT计数，不加正式成绩。正式保存复用已有服务和幂等 request_id。用户清晰发出“保存这次参考实验”或点击展示参数后的按钮即可授权，无须每次再弹一次确认；模型建议本身不能执行写操作。

ActionProposal 必须可供用户检查。执行时服务器重读自己保存的提议和业务状态；不能信任浏览器提交的 owner/分数/状态/工具名。参数已修改时重新验证并展示新参数，不偷偷执行旧版本。重复点击/旧卡片/刷新只复用同一业务请求，不重跑一次正式提交；两个数据库之间不宣称全局 exactly-once。

SSE 只传公共结构，不执行模型 HTML/JS 中的动作。卡片应经 Guard 后与消息持久保存，刷新与实时显示相符；取消/失败/未完成消息的卡片不能继续执行。普通文本、既有 RootDiagnosticCard 和旧历史继续可用。跨页面/会话/记录切换必须绑定发起时的 snapshot，禁止旧回答更新到新实验；退出清理 owner 状态和流，页面卸载处理取消并保留草稿。
