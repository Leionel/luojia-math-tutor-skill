Chapter 00

系统现状深度剖析：已有架构与代码实现到底是什么？

Baseline Audit

在启动 2.0 之前，必须准确理解当前公开仓库中已经沉淀的工程实现。项目绝非一个普通的 Chatbot 或简陋套壳，而是已经拥有基于 LangGraph 的多节点工作流、多模态公式解析、SymPy 符号沙箱与 BKT 记忆系统的成熟全栈底座。

1.0 运行时状态机流转拓扑 (LangGraph Topology) apps/api/app/tutor/graph.py
1. LangGraph 状态机编排 apps/tutor/graph.py

基于 StateGraph(AgentState)，全局状态字典拥有 28 个强类型键值（包含 pedagogical_action, verification_mode, hint_level, verifier_result, evidence_pack 等）。路由根据意图判断是否调用证明脚手架（proof_tutor）、诊断出题（examiner）或 LLM 二次验算（verifier）。

2. 极速上下文异步并发 fast_context.py

设置 0.35 秒严格超时阈值，并发启动拉取会话历史、关键词粗筛、文档片段切分与 SymPy 符号代数演算等协程。若学生发送截图，由 VisionParser 调用 MinerU 提取 LaTeX 公式后再入流。

3. 确定性符号验算沙箱 math_tools/verifier.py

拒绝大模型的心算幻觉。利用 step_checker.py 与 code_executor.py，在子进程隔离环境中运行 SymPy，通过代数等价性化简判定学生中间推导是否正确，并精准提取错因类型（Mistake）。

4. 记忆与掌握度追踪 memory/mastery.py

底层采用 SQLite Repository 记录每轮会话与题目尝试。mastery.py 维护基于提示等级（0-3 级）的掌握度动态增减分逻辑，并在前端实时呈现掌握度标签与能力雷达。

🔍 现状瓶颈：现有 1.0 架构在面对高阶专业课程时的“三大硬伤”
  • • 检索层过浅：apps/api/app/knowledge/search.py 仅用简单的正则表达式在内存字符串中匹配关键词加分，无法感知数学充要条件，也无法做知识图谱的多跳因果溯源。
  • • 知识与教学脱节：现有的 KnowledgeUnit 只是静态文档字典，没有 TaskMode（练习/概念讲解），更没有 TeachingCase（教学任务中间层），大模型无法得知当前题目的启发探针与保密策略。
  • • 图谱沦为“花架子”：前端用 React Flow 画出了图谱，但后端状态机并没有把“课程边界（ScopeLevel）”作为图遍历剪枝规则，依然容易向学生漫无边际地胡说超纲内容。
Chapter 01

核心公理与设计哲学：拒绝本体污染

✕ 常见严重误区：问句即节点 (Query as Node)

让学生在聊天中的每个不同问句（如“牛顿法一定收敛吗”、“为什么初值选远了会发散”）直接由大模型提炼为一个知识图谱节点。

• 图谱迅速退化：本体丢失结构，沦为千奇百怪的问句垃圾桶。
• 边界完全失控：大模型擅自将课外杂音永久化写入课程知识。
• 虚假关联泛滥：LLM 猜测的错误因果边永久留存，误导后续学生。
✓ 珞珈 2.0 准则：教学案例归纳 (Case as Abstraction)

学生问题是交互证据；教学案例是归纳抽象层；知识节点才是正式课程知识本体。

• 本体权威严密：正式课程知识必须由教师版本化发布，受大纲保护。
• 任务结构抽象：成百上千个问法归并至有限的结构化 Teaching Case。
• 演化受控安全：新提问流入候选区缓冲，累积证据经教师审批后入图。

11部顶会前沿文献理论基石 (Literature Grounding)

本方案中的每一处工程模块，均在 2023-2026 年国际顶级计算语言学与教育人工智能会议（CHI, ACL, EMNLP, NeurIPS, AIED）中找到了严格的研究依据支撑：

OATutor CHI 2023

建立集中式 Skill/KC 模型，强调内容库与平台的解耦，学生个性化通过 BKT 掌握度叠加，绝不克隆整图。

MathTutorBench EMNLP 2025

证实“强解题器不等于强导师”。Teaching Case 不能是标准答案缓存，而是涵盖教学任务类型的契约。

StatusKT Findings ACL 2026

坚持从“真实解题过程（Process Event）”提取学生证据，严禁把大模型猜测的心理状态直接当真值。

LongTutor ACL 2026

长期辅导信息不能粗暴塞进最近100条聊天，而是严格按“证据获取 $\rightarrow$ 状态诊断 $\rightarrow$ 教学动作”链路执行。

MalruleLib ACL 2025

把错因变成可执行过程（Executable Misconception）。在数值分析中细分条件错、算法错与浮点舍入Bug。

Confirming Correct BEA 2026

指出 LLM Tutor 极易误拒合法非标准解法。Teaching Case 必须显式维护 allowed_alternatives 替代路径。

StratL / EDF Findings ACL 2025

教学策略表达为：state/evidence $\rightarrow$ pedagogical decision $\rightarrow$ feedback，而非死板的一问一答匹配。

SciCode-Verified NeurIPS 2024

科学计算中的验证脚本自身也必须被审计。Teaching Case 需绑定带版本控制的 ToleranceSpec 与 Oracle。

KITE & EduGuard SOTA RAG

证明普通“课程RAG+Tutor”已非核心创新，真正的壁垒是显式课程边界、跨表示证据与自主迁移评测。

Chapter 03

四大核心对象详细建模规范 (Schema Definitions)

核心抽象：CanonicalTeachingCase (教学案例契约) case_schema.py

连接学生多变提问与课程知识本体的“中枢交换机”。记录了必须满足的数学充要条件约束、启发式探针、答案保护策略与数值验算沙箱配置： 

@dataclass
class CanonicalTeachingCase:
    case_id: str                          # e.g., "CASE_NEWTON_LOCAL_CONVERGENCE"
    course_id: str                        # e.g., "numerical_analysis"
    course_version: str                   # e.g., "2026.1"
    title: str                            # "牛顿迭代法局部二阶收敛条件与初值敏感性分析"
    task_type: str                        # "CONDITION_CHECK" | "ALGORITHM_TRACE" | "CODE_DEBUG"
    task_mode: str                        # "independent_practice" | "concept_explanation"

    # 锚定的稳定课程本体
    concept_ids: List[str]                # ["NEWTON_METHOD", "TAYLOR_EXPANSION", "SIMPLE_ROOT"]
    required_conditions: List[str]        # ["f'(x*) != 0", "f \in C^2", "x0 sufficiently close to x*"]
    related_misconceptions: List[str]     # ["MISC_NEWTON_GLOBAL_CONV", "MISC_RESIDUAL_IS_ERROR"]

    # 教学决策与防剧透策略 (对标 StratL & Confirming Correct)
    diagnostic_probes: List[str]          # ["请检查在发散区间内导数 f'(x_n) 是否出现趋近于零的情况？"]
    accepted_variants: List[str]          # 允许的公式/文字等价变体
    allowed_alternatives: List[str]       # 允许的合法替代解法（防止一刀切拒判）
    disclosure_policy: Dict[str, Any]      # {"solution_release_allowed": False, "max_hints": 3}
    oracle_spec_id: str                     # 绑定的数值沙箱基准运行脚本，如 "ORACLE_NEWTON_ARCTAN_CYCLE"
    review_status: str                      # "canonical" | "draft" | "deprecated"
Entity 2

KnowledgeUnit (课程本体)

相对稳定、由教师审核的正式知识对象。分为 12 种类型（Concept, Theorem, Condition, Algorithm 等），显式携带 scope_level 与来源版本号。

Entity 3

QueryRecord (交互证据)

永久保存学生原始文本、规范化表述、关联会话、命中 Case 与边界判定结果。仅作为行为证据池，绝不能随手直接创建为知识节点。

Entity 4

GraphCandidate (演化缓冲)

未被现有图谱覆盖的新疑问或大模型抽取内容暂存于此，记录支持证据计数（support_count），等待教师后台审查（Approve/Merge/Reject）。

Chapter 04

三级判别漏斗与排他比对 (Case Matcher)

🔍 经典反例：为什么仅靠大模型向量相似度判定是彻底错误的？
Query 1 (单根求收敛阶): “牛顿迭代法什么时候满足二阶收敛阶？”
数学条件：单根 $f'(x^*) \neq 0$ ──► 收敛阶 $p = 2$
Query 2 (重根求收敛阶): “重根情况下牛顿法的收敛阶是多少？”
数学条件：重根 $f'(x^*) = 0$ ──► 收敛阶退化为线性 $p = 1$

两者的 Embedding 余弦相似度高达 0.93。若采用简单去重或纯向量检索，系统将误归入同一回答；但两者在数学必要条件上发生排他性冲突，必须属于不同 Teaching Case！

一级：候选粗筛 (Retrieval)

利用 BM25 稀疏符号匹配 + 稠密向量嵌入，从 TeachingCase 抽象库中召回 Top-3 候选。

二级：结构特征硬过滤 (Structural)

比对 required_conditions。若检测到单根 vs 重根等物理排他冲突，一票否决合并请求。

三级：语义裁决 (Semantic Judge)

仅在模糊区调用 LLM 输出规范 JSON：SAME_CASE, VARIANT_OF_CASE, RELATED_CASE, NEW_CASE, UNCERTAIN。

Chapter 05

课程知识边界契约与动态演化 (Boundary & Evolution)

core 大纲必修

课程教学大纲内必须掌握的核心知识。如：牛顿求根法、局部收敛阶。

prerequisite 前置基础

理解核心所需的前置定理。如：连续函数介值定理、Taylor展开。用于卡点时向前溯源。

extension 受控拓展

直接相关的高阶内容。仅在学生主动深度追问时展开。如：优化中的 Newton 法。

external 边界阻断

超出课程范畴（如拟牛顿法 BFGS）。触发响应护栏（Response Guard），温和告知超纲。

知识动态演化合法路径 (Promotion Routes)
• Route A (教师直达): Teacher Manual Proposal ──► Review ──► Publish Canonical Node
• Route B (课程资料提取): Teacher Slides/Textbook ──► LLM Extract ──► Candidate ──► Teacher Approve ──► Course Graph
• Route C (高频疑问聚类): Repeated Student Query Cluster ──► Candidate Case ──► Teacher Review (Approve/Merge/Reject)
★ 核心准则：Merge 优先于 New Node（优先作为别名、变体或证据追加，严控本体节点膨胀）。
Chapter 06

学生认知叠加态建模 (Student Overlay)

借鉴 OATutor 与 StatusKT 的核心设计：绝不能为每个学生克隆一张专属知识图谱。课程知识图谱全局唯一受控，学生状态以切片表（Overlay Table）叠加于课程图之上：

1. 节点级掌握度 (StudentUnitState)

• mastery_estimate：基于 BKT 贝叶斯知识追踪动态更新的掌握概率 [0.01, 0.99]。

• independent_evidence_count：脱离任何 AI 提示独立解对的严格证据计数。

• recent_error_refs：指向最近触发的特定错因历史引用。

2. 案例级表现 (StudentCaseState)

• exposure_count：学生接触该类型教学案例的累计次数。

• max_help_used：最高消耗的提示等级（0=独立完成，1=探针提示，3=完整推导）。

• independent_transfer_status：面对同构变体题时的独立迁移成功状态。

Chapter 09 · Final Invariants

终局守则：坚决不踩的九大禁令红线 (The 9 Invariants of What NOT to Do)

方案第 16 节明确裁定的工程红线，任何破坏以下准则的伪创新都将导致系统崩塌与烂尾

1. 绝不迁移 Neo4j

单门专业课仅有数百个知识单元，在内存中使用 NetworkX + JSON/SQLite 速度极快且完全可审计。盲目引入外部图数据库只会带来沉重的部署包袱与分布式事务灾难。

2. 绝不全课程一次性建图

严禁脱离真实教学去把整本《数值分析》全书一次性搬上图谱。必须坚持单点突破：仅对“非线性方程求根”这一个单元打穿闭环。

3. 绝不让每个 Query 建节点

永远记住“Query is Evidence”，学生聊天问题绝不是知识节点。把每个问句变成图节点会导致图谱灾难性退化为垃圾堆。

4. 绝不多Agent自由辩论建图

严肃理科教学真理来自教师讲义与学术严密推导，严禁让多 Agent 之间通过自由对话去决定课程定理与因果边。

5. 绝不搞全自动本体提取

大模型自动抽取出的知识点与关系，必须无条件流入 Candidate 暂存区，经由教师端审核确认后方可合入图谱本体。

6. 绝不为学生复制全量图谱

坚守 $G_{student} = G_{course} + S_{student}$ 公理。课程图全局唯一，学生个性化仅为节点与案例上的轻量状态切片。

7. 绝不大改八级提示策略

在验证动态图谱与 Case 层的过程中，保持现有教学流与提示策略稳定，严禁多个底层核心同时重构导致无法归因。

8. 绝不为动态图谱引入复杂 GNN

知识图谱的首要目的是解决**教学组织与因果约束**，而不是作为算法炫技。严禁在没有海量图数据前引入沉重的图神经网络。

9. 绝不单靠 Embedding 去重

向量余弦相似度无法识别单根与重根的本质冲突。必须保留基于必要数学条件（Required Conditions）的结构化硬过滤。
