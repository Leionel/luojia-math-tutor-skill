# R6.1 执行报告

日期：2026-10-16。分支：`feature/course-graph-2.0`；起点 `47d60bc`。保留执行前的工作树改动；本轮没有 commit 或 push。

## 1. 原有问题与实际发现

- `/explore`、实验领域导航和私人图持久化已经存在，无需重建入口或数据库。
- 原探索只接受 GS；建议是固定模板，缺少由模型根据当前主张设计实验的路径。
- 私人关系只有编辑表单，没有独立节点—边查看页；Chat 的线性引用缺少探索上下文。
- 五个一级入口适合保留，教师审核入口原本对普通学生可见。
- R5 冻结摘要在 Windows 本机通过，但 `cases-v1.json` 的 Git 对象为 LF，冻结字节为 CRLF；需固定检出格式。

## 2. 主要修改

- **发现与恢复知识积累**：`/graph` 的课程/私人双视角，按当前账号的真实探索选择节点与关系，展开主张、说明、理由、来源，返回探索或 Chat。不同探索不自动合并。按追加要求扩大私人网络工作区，并将桌面详情侧放。
- **提出问题到实验**：从 Chat 工具菜单带服务端会话 ID 发起探索；读取并保留原问题。模型建议包含条件、检验目的、观察量和结构化任务；GS/Newton 共用流程，参数可编辑，确认后才执行真实运行器。
- **通过结果修订**：预测、计算、矩阵判据、模型意见与学生修订分开保存。模型建议及候选关系可恢复；私人关系支持确认、编辑、拒绝与历史恢复。
- **带着历史继续讨论**：规范探索引用由服务端读取原主张、修订、所选/近期计算和已确认关系，复算后进入现有 Chat 编排与消息持久化；刷新可恢复引用。

## 3. 关键技术决策

复用 CourseStore 学习记录、TeachingDecision、现有模型适配器、GS 和 Newton 运行器；不增加数据库表或平行 Agent 编排。`StructuredExperimentProposal` 为同一教学决策协议扩展有类型任务。

私人关系进入统一探索上下文，生成具体的关系复查焦点；后续建议需引用相关私人关系。课程来源审核状态、个人判断和受控计算的范围分别保留。上下文只选择少量关系和计算，8KiB预算内传递，超限显式提示。

实现说明、端点、操作步骤与复现命令见 [R6.1 连续探索](../docs/r6.1-exploration.md)。
