# B4 四个公开开发变体的核对笔记

这是 Agent 准备的讨论依据，**不是真人 gold**。给盲审者先提供 [`review-packet-v1.json`](review-packet-v1.json) 中的 B4-V01–V04 代码和问题，收回答后再打开本文件核对分歧。两个文件都在仓库中，不能把这种顺序管理称为技术上封存的盲测。

- **V01**：从作业初值 `x₀=1`，正确 Newton 更新先得 `1.5`，随后点在 `[√2,1.5]`；因此实际停止点在 `[1,2]` 时，`f(x)=x²−2` 的导数下界为 2，中值定理给出 `|x−√2|≤|f(x)|/2`。若 `fx` 确为 `f(x)`，直接 `|fx|≤tol` 的**该停止分支**足以满足根误差 `≤tol`。这不证明任意 `x0`、`max_iter` 耗尽或整段函数都正确。静态提示应承认这项合法可能性。
- **V02**：`(x+2/x)/2 = x−(x²−2)/(2x)`（`x≠0`），对作业初值是等价 Newton 更新。`|fx|/2≤tol` 在上述区间同样是足够的根误差停止条件。规则未命中不等于自动证明代码正确，仍须检查前提与迭代上限。
- **V03**：更新写成 `x+fx/(2x)`；从 `x=1`、`fx=-1` 得 `x₁=0.5`，与 Newton 的 `1.5` 不同，且已离开给定 `[1,2]`。不能沿用 V01 的区间下界去给后续停止分支担保。应指出更新符号问题，同时不要把“残差比较”本身当唯一错因。
- **V04**：`fx=x−2` 不是作业函数值 `x²−2`；代码即使命中 `abs(fx)<=tol`，也不能把它当原函数残差界。静态 AST 看见变量名 `fx` 不构成语义证明，应追问 `fx` 的定义。

审核时分别判：数学正确性、静态规则是否命中、文案是否误导、对该代码能否形成整体正确性结论。四条样本是公开开发反例族，不能据命中数计算误报率或准确率。若真人意见发现上面的条件或推导有错，先改材料并重建摘要，旧审核包失效。
