# R7.0 逐题审核与真实运行准备

本包是公开开发材料，作者与独立数学审核均 pending。复用 [R5 原题与 rubric](../r5/cases-v1.json)、[R64 十一维审核合同](../r64/rubric-v1.json)；以下细化不修改冻结 gold。六个独立保留名额仍未分配。本包不产生未见题成绩。

## 逐题判据

| 题 | 必须保留／允许的等价路径 | 禁止结论、首错和 unknown |
|---|---|---|
| E06 | 已知 x>0，sqrt(x²)=abs(x)=x；直接解释正数分支合法 | 不可忽略 x>0 用负数反例否定本步。当前有限 checker 拒绝额外条件不代表数学未知或学生错 |
| E08 | 对 x²+7 求导为 2x，因此是一个原函数；任意常数替换仍合法 | 不可因未写 +C 判该候选错误；不可说这一个候选列出了全部原函数 |
| E10 | 步骤1的乘积法则正确；可写 exp(x)(1+x) | 最早错误在步骤2删除 x exp(x)，不能说步骤1错；只在 x=0 相等不构成恒等式 |
| N01 | f(0)=2，f'(0)=-2，x1=0-2/(-2)=1 | 正确一步不证明后续收敛；不应因后来周期否定这一步 |
| N02 | f'(0)≠0 只保证该点 Newton 商有定义；代入可得 0↔1 反例 | 全称收敛推断不成立；不推断所有负初值、完整吸引域或唯一分界 |
| N03 | 充分条件未满足，仍可能收敛；先纠正逻辑，再问函数、初值及方法 | 实际收敛性 unknown；不可补造函数，也不能把“充分条件未满足”当发散证据 |
| N04 | f(x)=10^-12(x-1)，x=0 的残差 10^-12、根误差 1；也可用精确线性解或导数下界计算 | 不可将残差直接当根误差；有 m=10^-12 时残差/m=1，不能凭小残差认证 10^-12 根误差 |
| G03 | 该矩阵 GS 误差矩阵特征值 0、1/5，故 rho=1/5<1；直接代数或正确受控计算皆可 | 行严格对角占优是充分非必要；本题矩阵已给，不应只追问矩阵；不能仅靠有限轨迹证明一般定理 |
| Q03 | 仅网格差不足；应明确 Richardson 估计依赖光滑／渐近模型，严格界需要额外论证 | 不可断言真实误差严格小于差值；未给函数、规则细节和导数界时具体真实误差 unknown。允许给光滑混叠反例，不可声称两网格对照就是严格界 |

本轮新开发见证 R7F01 不混入以上九题的真实模型分母：Newton 对 `sqrt(x)-2`，轨迹 `[1,3,4,-1]` 或 `[1,3,4,"NaN"]`。更新函数为 `4 sqrt(x)-x`，1→3 正确，3→4 已错，首错 k=2；后面非法值不能遮住它。有效替代是将 x2 改为 `4 sqrt(3)-3`，此时才定位后面的非法观察 k=3。不动点 `g(x)=(x+4)/2`、轨迹 `[0,2,4,-1]` 同样首错 k=2。仅核对有限轨迹及已声明规则，不证明一般收敛。回执见 [before/after](first-error-before-after.json)。

私人九对复用 R64 的 GS／Newton／积分 × 相关／无关／失效。相关时应追问原主张与后来修订为何不同；P1 不得复述为已证事实。无关或来源失效时，不能将旧意见补成本题条件，不以其他来源替换。只按实际回答片段评分；选中了上下文不自动给“有帮助”分。

每题都使用十一维 rubric；不适用须说明理由，未审核保持 null。首错指标只在可定位输入上评分，不能要求 N03 给出不存在的错误行号。严重错误包括否定上述正确步骤、量词逆推、伪造参数／记忆、误把估计升格为界、帮助泄露。允许合法等价计算，不按固定文案评分。记录 reviewer、时间、回答原句、数学依据、版本／摘要、失败分类和争议处理；独立性须由真实参与者记录，工具不能认证签署者身份。

## 离线生成审核包

从仓库根目录执行，所有输出用新名字，旧失败保留：

```powershell
python scripts/r64_r5_capture.py --offline --case E06 --case E08 --case E10 --case N01 --case N02 --case N03 --case N04 --case G03 --case Q03 --output results/r7/new-r5.json
# 上一命令完整保留 R5 的 72 计划项；只选择 27 次，退出 1 表示全量计划未完成。
python scripts/eval_r64.py --offline --capture --output results/r7/new-private.json
python scripts/r7_quality.py --prepare results/r7/new-r5.json --private-report results/r7/new-private.json --output results/r7/new-packet.json
```

审核包有 27 次 D0/D1/D2 + 18 次私人配对 = 45 条未运行记录，保存真实编排所得完整 Teacher 输入和摘要，rubric 与逐维评分模板。R5 的完整 72 和 R64 的完整 105 分母没有缩小或覆盖；45 是本次单独版本的精简计划。输入中的上游模型审核仍为 fixture。私人的非个人提示投影保持相同；模型、温度、输出上限相同，实际输入 token 因上下文而异。

## Live 入口与预算

`scripts/r7_quality.py --live <packet> --approval <approval.json> --output <new-results.json>` 是可执行的**最终 Teacher 输入回放**。它不调用原生实时路由、检索、工具、回复修复或保存链路；D2 不得写成完整 Agent 真实成绩。原生全路径真实比较仍待接入，不能把回放结果与 R64 E0 混算。

本轮没有调用此入口。现有密钥和此前已用完的调用授权都不能授权新实验。未来运行前须在明确的新授权中指定供应商、endpoint/model/version、外发的准确输入、总请求、输入／输出 token 与费用上界，并完成作者和独立数学复核。环境仅接受临时 `R7_REPLAY_API_KEY`，不读 dotenv。

approval 字段模板见 [approval-template](approval-template.json)。`packet_sha256` 使用 `r5_quality.sha(packet)`（UTF-8、ensure_ascii=False、sort_keys=True 的 JSON）计算。`input_tokens_upper_by_messages_sha256` 须来自与目标模型相符、含消息包装开销的审核测量，脚本不把字节数冒充 token。计价来源必须覆盖输入、输出、推理及其他计费项，明确最大请求单价及币种；不支持无法给出上界的服务模式。填写引用字段是提交者的声明，不能代替实际授权或审核。

建议首批先做九题 D0/D1/D2 的 27 次，再单独授权私人 18 次；若要分批，分别生成、审核并冻结对应包，不能删除既定失败项。全部 45 次、每次 1536 输出 token 的计划上限是 69,120 输出 token，不是费用报价；输入需逐条测量，总费用上限至少覆盖 `请求数×单次最坏费用`。当前供应商、模型、输入 token、单价和费用均 null，无法诚实报金额。该入口每次发送前复用 S5 SQLite 原子预算预留，失败不退额、无重试，首个失败后保留其余 not_run；每次最多 45 秒并记录 provider usage、截断、HTTP 状态、延迟与返回模型。报价上界的正确性仍依赖供应商合同与真实审核，不等同已验收计费。

回放完成后，先由独立审核者对盲化顺序的回答评分，再用 R64 配对合同输出逐对差异、退化与不确定性。不得让固定回复取得真实质量分；小样本公开题不支持总体显著性或学习收益。E2 真人须另有同意和任务日志；E3 须由独立作者提供迁移题及延迟测验，不使用当场参考实验成功代替。
