## 请求与时延：哪些有证据

同一“创建 → 建议 → 计算 → 接受私人关系”流程中，保存后的目录 GET 从 **3 次降至 0 次**。原探索相关请求为 4 POST + 3 GET，修复后为 4 POST；使用已返回的保存对象更新本页目录，不缓存或跨 owner 共享业务数据。来源目录改为首次展开编辑时读取，再展开不重复请求，浏览器实测 1 次。

新会话原先额外请求 `/tutor/generate_title`，后端会调用模型。现在从首句生成可手动修改的标题：浏览器实测该请求 **1 → 0**。模型响应被人为丢弃但服务端已保存的回归中，显式恢复只发 GET，建议 POST 总数为 **1**；未添加自动付费重试。

代码审查确认：探索建议服务端上限 45 秒、浏览器等待上限 55 秒；恢复读取上限 15 秒；底层模型 HTTP 请求上限 60 秒。没有为演示缩短输出预算或修改模型数学判据。旧 R6.1 回执中，截断批次为 10.14–11.51 秒，关闭额外推理后的三次请求为 3.47–5.68 秒；后者虽传输成功，教学语义仍未全部通过。这是旧版本观察，不是当前版本性能分数，也不据此归因或宣称加速。

本轮模型文本固定，真实 runner 执行。夹具点击建议到进入编辑的时间含浏览器自动等待，不等于真实供应商延迟；真实模型费用、时延分布、移动设备性能、多用户负载均未复测。首句标题减少了自动数学主题分类，用户仍可重命名；外部字体与配置下的 Desmos 依赖仍需目标网络验证。

## 浏览器验收与失败保留

使用生产构建，1440px 桌面与 390×844 手机视口。最终 7 项自动化任务包括：

1. Chat → 原主张探索 → 编辑预测/受控计算 → 返回同一会话。
2. 保存计算 → 引用讨论 → 刷新回答 → 回到原探索版本与计算。
3. 私人图不选节点，直接用 Enter 返回原探索。
4. 修订 → 学习记录 → 选择旧版本 → 清空草稿/刷新；不覆盖当前主张。
5. 服务端完成建议后丢弃响应 → 读取已保存建议，不重复模型 POST。
6. 合成私有资料 → 引用对话 → 恢复实际原文；延迟恢复时输入保护。
7. 手机 Enter/Space、长参数、真实示例计算、保存表格和长公式内部滚动。

资料使用隔离库中合成的已解析文本，不验收外部 PDF/MinerU 解析。认证使用合成身份，不是生产 JWT 验收。沿用 R6.4 类型化路由夹具；因此不评价原生模型路由或教学质量。真人参与者为 0，不能从 7 项功能通过推出学生完成率或学习收益提高。

原始失败均在本机保留：

- `after-dev-browser.log`：路由夹具误用建议 JSON，首项未到预期生成路径，下游缺有效探索 ID；不视为可比学生任务样本。
- `after-dev-v2.log`：夹具启动时用了本机 FastAPI 不支持的生命周期方法，该轮中止；改用 lifespan 包住现有 R6.4 适配器。
- `after-dev-v3.log`：6/7 完成，私有资料任务暴露真实输入清空问题；`material-before.log` 定向重现。
- `after-production.log`：根节点宽度断言虽通过，截图复核发现内部溢出。`mobile-audit.log` 记录 385px 容器/1088px 内容，修复前截图另存，未覆盖。
- `after-production-final.log`：最终任务、请求测量与更严格的内部滚动检查。原始 CLI 日志同时保留具体操作代码。

可移植摘要、源代码和图片摘要见 [机器证据](acceptance-2026-10-18.json)。完整本地输出位于 `results/r65/`、`output/playwright/r65-*`，隔离数据库不提交。
