## 这次采集确实观察到了什么

`results/r5/offline-release.json` 的 72 次 ASGI/SSE 运行完成，72 份完整 artifact 以摘要绑定。采集脚本、材料和配置在运行期间保持一致。模型全部固定，不存在真实模型数学正确率。

24 题中，22 题到达受控生成阶段，输入、空初态、fixture、生成配置和调用预算相符。**N03、Q03 未进入受控生成，三个组都只有上游固定回复调用**。这两题的干预控制尚未建立，单列为不可比较；不能因为 HTTP/SSE 完成就算公平对照成立。应先修采集适配并重跑同题，不能据此判项目数学错误或模型退化。

## 数学材料的审阅重点

- N01/N02：保留正确的第一步与导数事实，拒绝全称收敛推广。
- N03/G03：没有满足充分条件，不能直接推出不收敛。
- N04/N05/G04/Q03：分别核对残差、步差、唯一性与严格误差界，避免将停止指标升级成数学保证。
- E06/E08/Q02：正数条件、常数原函数及不同合法求积规则不应被误判。
- E09/E10/G02：区分结论、证明充分性与最早错误位置，保留前面的正确步骤。

这些判据仍为待审核材料。24 个公开题不构成未见测试集，6 个保留题名额尚无题目。

## 原型中修复的交互问题

1. 首页原先提前显示周期结果，泄露预测任务答案；现在观察后才揭示。
2. 讨论与原预测未完全绑定任务/运行；现在按运行和步骤分开显示讨论，原预测保留在当次快照。
3. 错误回访原先跳往通用 Newton 条件页；现在进入残差与根误差的针对性复习和新数值题。
4. 帮助状态、布局 URL 与键盘跳转采用可恢复状态；原型标签仍不能代替正式服务端帮助回执。

以上只改独立原型，未替换正式页面。早期截图和采集失败仍保留在 ignored 输出中，包括首版报告超过 S5 2MB 上限的失败；后续改用摘要绑定的逐运行 artifact，没有放宽输入上限。

## 对三个研究问题的回答

**数学能力是否优于普通 LLM？** 尚不能判断。现在能定位工具覆盖与控制缺口；真实模型、独立数学评分和学习收益证据不足。

**功能组织是否合理？** 领域服务和规范引用值得保留；独立入口、命名与重复容器增加了组合成本。应先统一任务、实验与记录入口，而不是合并数据库或增加 Agent。

**能否形成连续学习过程？** 原型展示了可点击的预测—观察—修订—新题过程，以及从错误回到相关任务；真人是否能理解并顺利完成，仍需用户选择布局后做任务验收。

## 后续优先级

1. 先完成数学材料独立审核及两个采集分支的协议适配，建立可信的失败判据与公平干预。
2. 选择原型方向后，复用现有 canonical ref 和领域 API 建立任务协调；保留独立检验的服务端边界。
3. 做记录的只读聚合和规范返回链接，明确参考帮助、纠错与独立检验各自的来源。

最值得研究的是：自然语言正确步骤的保留与最早错误定位；条件不足时恰当 unknown；确定性证据何时真正改善教学反馈。真实模型实验须另获授权、预算和发送前控制。
