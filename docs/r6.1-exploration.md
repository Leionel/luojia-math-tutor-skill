# R6.1：连续的数学探索

从 Chat 的问题出发，保存主张，由助教建议可编辑实验，确认后计算，再修订并回到同一对话。私人知识网络按探索展示这些积累。

## 当前代码发现

实施基线为 `feature/course-graph-2.0` 的 `47d60bc`。`/explore` 和实验领域导航已经存在；本轮扩展它们。原探索的参数只接受 GS，默认建议为固定矩阵，私人关系没有节点—边查看页。原 Chat 引用能核验一次线性计算，但缺少所在探索的原始主张、修订与私人关系。

开始时工作树已有评测脚本、Notebook、学习记录和文档改动，均保留。Notebook 的字数计算移除了一处被 React Compiler 拒绝的手工 memo；未重写该页的现有改动。

## 学生操作

1. 在 Chat 提出问题，打开“按需打开工具 → 围绕当前问题探索”。服务端检查会话归属，从已保存的最近学生问题生成探索草稿；URL 仅含会话 ID。
2. 核对主张并保存。点击“让助教分析并建议实验”，查看已知条件、待补条件、检验问题与观察量。无模型时显示不可用，可使用明确标注的 GS 默认示例或手工填写 Newton。
3. 采用建议后可分别修改每组的函数/矩阵、初值、阈值和预算。填写自己的预测，确认后执行。模型建议本身不会运行数学工具。
4. 查看真实计算的轨迹；GS 二阶矩阵另列有理数谱半径。Newton 的有限轨迹与停止诊断不构成一般收敛定理。依据观察修订主张并写理由。
5. 对建议关联选择加入草稿、修改后保存，或拒绝。历史保留原主张、图版本、建议、计算和修订；可恢复私人图。
6. 从计算卡继续讨论，使用当前探索版本和所选计算；若探索源于 Chat，返回原会话。刷新 Chat 会从已保存消息的规范引用重新解析上下文。
7. 以后从“我的知识网络”选择探索，点击节点查看主张、说明、关系理由及来源，回探索编辑或继续讨论。

## D：建议生成与执行

`POST /api/explorations/{id}/advice` 使用当前保存版本，通过现有 `OpenAICompatibleClient` 请求一个教学决策。`StructuredExperimentProposal` 扩展同一 ExperimentProposal 契约族，提供1至2个有类型的 GS/Newton 任务。普通 Chat 的既有 Newton 单参数建议仍保持原协议。

模型响应由 Pydantic 校验任务、来源引用、候选图和教学动作。缺少可靠检验工具时可返回澄清或解释，不强制生成实验。建议保存为探索历史；运行仍由独立的 `/runs` 请求携带学生预测与明确确认触发。

GS 复用 `run_numerical`，Newton 复用 `LearningWorkspace.lab` 与 `run_reference`。保存、版本冲突和重试沿用原探索事务。旧 `gs-exploration-v1` 标识继续可读，新增任务类型是兼容扩展，无数据库迁移。

## E：私人关系参与后续教学

候选关系尚属模型意见，只有学生核对并保存才进入私人图。拒绝会记录理由；编辑和恢复沿用原图历史。没有自动合并不同探索的概念。

后续建议与 Chat 使用同一 `exploration_context`：选择最近四条已确认关系、对应节点及少量尚未连边的概念和来源，优先选“推出/质疑”关系作为 `teaching_focus`，把具体的两端概念、原理由和可对照计算交给教学决策。模型建议若忽略应复查的私人关系引用，不作为有效建议交付。此约束保证关系进入决策证据，不能保证模型解释的数学质量。

## F：探索引用与权威层级

`ExplorationContextRef` 仅携带 `record_id`、`revision` 与可选 `selected_run_id`。服务端检查 owner 和 revision；选中计算必须属于该探索。上下文选择所选计算及最近计算，默认取最近两次；轨迹选取有限步骤，附带省略数量，整体受8KiB预算约束。较长内容超预算时明确报错，不悄悄截去必要条件。

原主张、当前主张与最近修订来自服务器；私人关系标为学生已确认、未经审核。课程/上传/笔记来源保留各自审核状态，变化的来源明确标记。线性运行复算轨迹和矩阵判据，探索 Newton 运行也复算后才进入上下文。模型不从保存 JSON 自称正确的字段继承数学结论。

Chat 复用现有 `/tutor/context`、`/tutor/stream`、Prompt builder、TeachingDecision、消息持久化与引用恢复。参考讨论保持 `verified=false`、`is_correct=null`、`mastery_delta=0`。
