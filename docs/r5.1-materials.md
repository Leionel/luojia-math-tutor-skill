# R5.1：统一资料管理与跨工作区引用

## 本轮完成

“我的资料”位于侧栏工具区，紧接“搜索对话与知识”。主导航保持原有五项。统一搜索合并历史消息内容检索与教材、笔记、错题检索，支持分类查看和继续原会话。

资料沿用 `documents.markdown` 与 `document_chunks`，没有新增资料库或数据库迁移。上传成功后只保存原文与索引；阅读、对话和生成笔记由用户选择。学生材料不写入官方课程图谱。

| 入口 | 行为 |
| --- | --- |
| 我的资料 `/materials` | 上传、查看原文保存状态、打开伴读、选择章节进入 Chat、转到笔记本 |
| 材料伴读 `/reading` | “+ 导入资料”使用同一上传组件，成功后自动打开新文档；保留选段、条件检查和阅读笔记 |
| Chat 附件菜单 | 分为题目图片、引用已有资料、上传新文档并引用；文档不再作为整份 Markdown 拼入用户消息 |
| 笔记本 `/notebook` | 先选择已有资料，再生成抽样笔记；新资料导入不会自动触发生成 |
| 错题本 `/mistake-book` | 资料复习收为次级操作，不因教材含有题目而新增学生错题 |

## 来源与失败处理

上传使用 multipart。原文、派生切块和上传文件归属在一个 SQLite 事务中提交；解析空结果、解析失败或存储失败都不会留下成功文档。列表的 `ready` 表示有保存的原文，`source_missing` 表示旧资料缺少原文，不能推断其旧解析过程。

上传是同步请求。页面只显示当前请求中、成功、失败；不提供后台进度或刷新后恢复承诺。网络中断时服务端可能已经保存，重试前应先刷新资料列表。限制沿用 200MB、PDF 粗略页数检查 200 页；它不是严格的 PDF 页数审计。

Chat 使用已有 `ReadingContextRef`：资料 ID、内容哈希、章节、字符范围。服务端按当前身份读取原始 Markdown，检查 owner、版本、章节、范围与帮助资格；引用最多 6000 个 Unicode 字符。引用快照保留在消息回执中。文档文字作为不可信数据进入来源上下文。

原文读取、上传前后与笔记生成前后检查独立检验限制；已有引用不能绕过 Chat 的服务端帮助校验。图片继续使用视觉识别路径；图片与资料引用分开发送。上传失败时保留问题与附件，不发送错误占位消息。

生成笔记关联真实 `document_id`，保存来源哈希、正文抽样字符数、原文字符数及章节大纲覆盖说明。来源元数据收入详情，旧笔记没有的版本信息不会补造。模型生成失败或生成期间来源变化，不删除原文，也不保存伪成功笔记。学习记录里的文档笔记返回笔记本，不再把 `document:…` 当作 Chat 会话。

全量 `npm test` 通过：API 1079 项、Web 114 项。随后增加统一搜索测试，定向回归 27 项通过，包含本轮 10 个 API 场景。新增 [API 回归](../apps/api/tests/test_material_reuse.py) 和 [Web 回归](../apps/web/lib/material-policy.test.ts)；测试均使用临时库及 Mock，不调用 MinerU 或付费模型。

生产构建生成 19 个路由；TypeScript 检查通过；ESLint 无错误，保留 10 项已有警告。文档链接检查通过。首轮全量曾因触碰内容审核绑定的服务文件而触发 R2 摘要过期；最终将 HTTP 阅读帮助检查放在 API 边界，服务文件与 R2 审核材料均未改变，原检查恢复通过。

桌面 1440px 与手机 390px 实际走查包括：上传后阅读、同文档选择章节发出 Chat 来源绑定、生成笔记、笔记失败仍可读、图片请求分流、上传失败零 Chat 请求、统一搜索恢复原会话、资料入口位置、手机抽屉与横向溢出检查。走查使用本地隔离服务和明确标记的测试 PDF；浏览器截图与命令日志在忽略的 `results/r51/`、`output/playwright/r51-*`。

## 未验证与 R6 接口

真实 MinerU 对 PDF、Word、PPTX 的解析质量、真实模型笔记质量和真人学习效果未验证。浏览器夹具不能代替真实供应商验收；现有 KaTeX 与开发环境警告也不计为数学能力证据。

未实现异步任务队列、资料删除界面、个人知识图谱或关系抽取。后续 R6 可沿用文档 ID、原文哈希与选段作为个人知识来源锚点；切块仍只是派生索引，不能替代原文，也不能自动产生审核通过的课程事实。
