# R6.2 私人历史进入教学决策

原缺口：R6.1 只在显式引用原探索时消费私人关系；新会话没有召回。候选建议只提供整图，没有逐条状态。真实模型还出现动作与实验字段冲突、候选边端点缺失，以及把未知比较量补成残差的问题。

现在的数据流：`learning_records(exploration)` → `personal_recall.select_personal_context` → 当前 Chat 的 `personal_context` → 原有 `TutorWorkflow` 提示和 `TeachingDecision.source_bundle` → 回答消息持久化元数据 → “为何联想到”及原探索链接。没有新建教学 Agent。

召回只检索同一 owner/course 的最近 50 条探索，最多选两条已确认关系、每条一项经过原引用协议检查的计算，总计不超过 7 KiB。相关性采用明确概念或数值方法与具体表述的交集；这是可审计的词面筛选，可能漏召回同义改写。关系保存 ID、探索 revision、内容摘要版本、权威类别、选择理由与原来源。不同权威放在同一证据包中仍保留标签，单凭私人意见不能输出 supported。

模型关系提议存入原探索的 `relation_candidates`，默认 pending。`POST /api/explorations/{id}/relations/decision` 支持 edit/accept/reject，检查探索 revision、候选 version、幂等 request_id。接受生成新的私人关系 ID，不覆盖旧意见；拒绝不加入图。原提议、编辑及决定保存在历史，`decision_receipts` 可刷新恢复。手工保存的关系仍属于学生私人确认。没有课程图写入、verified 或掌握更新。

旧来源无法按原版本解析时，该关联不参与召回；选取后在交付前再核对版本与来源，失效则本轮失败，不自动替换。失效的实验不能贡献轨迹，仍可讨论与其分开的私人判断。UI 将本轮快照与当前探索分开：链接打开当前原探索，消息保留当时所选版本。

`tests/test_personal_recall.py` 用 SQLite 真持久化覆盖相关/不相关/旧来源变更、重开数据库、用户隔离、候选编辑与接受拒绝回执、旧版本拒绝。有/无上下文通过同一个真实 Chat 编排路径，模型回复使用 fixture；实际选取和行为输出在 `results/r62-comparison.json`。这证明编排差异，不证明教学质量改善。
