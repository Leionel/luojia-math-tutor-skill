# R6.3 持续探索流程

先复现了 R6/R6.1 的 GS 纵向流程和 Newton 保存、修订、引用回归，再扩展积分。没有增加另一个 Explore 页面或 Agent。

## 原有差异与共享边界

| 环节 | GS | Newton | 数值积分 |
|---|---|---|---|
| 主张 | Explore 持久化 | R6.1 Explore 已接入 | 原先只在 numerical-lab，现接 Explore |
| 预测 | Explore 执行事件 | 原 lab 与 Explore | 原 numerical-lab 与新增 Explore |
| 运行 | 线性迭代 runner | 原 Root runner | 原 quadrature runner |
| 证据 | 残差、二阶有理数谱半径 | x、f(x)、相邻步与停止理由 | 近似值、细分差、估计、求值次数 |
| 修订 | 版本化原话与理由 | 同一探索历史 | 同一探索历史 |
| 恢复 | CourseStore | CourseStore + lab | CourseStore + numerical_lab |
| Chat 交接 | exploration / linear_lab ref | exploration / root_lab ref | exploration / integration_lab ref |

统一数据流：保存主张 → 同一次模型调用读取有界上下文与任务 schema → `ExperimentPlan` 提议 → 学生编辑参数、比较因素及理由 → 填预测并明确确认 → `Explorations.update` 事务 → `exploration_runner` 薄适配 → 原 runner 与原实验存储 → 版本化结果与主张修订 → 原探索 Chat 引用，或 R6.2 在新问题中按相关性召回。

`ExperimentPlan` 保存待检验主张、已知条件、局部问题、领域任务、变化因素、保持因素、观测量、数学理由及工具限制。因素使用任务字段名，服务端核对两组实际差异与声明一致。计划参数须与确认参数相同，计划主张须与当前主张相同。编辑不会自动确认；刷新不会恢复确认勾选。

原始模型建议保存在 advice 历史，确认时的计划保存在 run 历史，两者不相互覆盖。`plan_origin` 区分手工、规则示例和学生编辑后的模型提议。数值结果仍标为受控参考计算，学生修订仍标为未经审核的意见。旧版无完整计划的记录仍可恢复，采用时补成可核对的计划。

## 三条实际计算

输入、预测、计划及建议修订见 [验收案例](../evaluation/r63/cases.json)，实际轨迹见 [计算回执](../evaluation/r63/local-run-receipts.json)。`test_shared_exploration.py` 经 HTTP API 创建探索、编辑预算、确认真实 runner、保存预测与修订、重新读取并生成 Chat 引用。设置 `LUOJIA_R63_REPORT_DIR` 为本地目录后运行该测试，可导出每例完整恢复快照。

| 案例 | 输入与控制 | 真实证据 | 建议修订 |
|---|---|---|---|
| GS | 保持 rhs、初向量与停止规则，矩阵由 [[4,1],[1,3]] 改为 [[1,2],[0.1,1]] | 第二组不严格行对角占优，精确 GS 误差谱半径 1/5 | 对角占优是充分条件，不是必要条件 |
| Newton | f=x³−2x+2，初值 0 与 −2 | 0→1→0；−2 的有限轨迹残差达标 | 不能声称任意初值收敛；循环可另做代数核对 |
| 积分 | x⁴，[0,1]，Simpson 初始分段 4 与 8，其余相同 | 近似值更接近 1/5，估计字段与严格界字段分开 | 步长对照支持局部观察，不把估计升为严格界 |

另有光滑振荡函数 `sin(8*pi*x)^2` 在 [0,1] 的反例：n=4、8 的网格混叠令估计极小并触发估计阈值，实际积分为 1/2，近似值却接近 0。这展示“估计很小”不足以给出严格界，不能把它解释成对所有光滑函数的可靠误差认证。

GS 的有限轨迹与二阶有理数计算各有限定范围；Newton 的有限数值输出不证明吸引域边界；积分的区间解析用来排除定义域问题，不证明导数上界。自然语言推广、严格误差界及教学建议仍需真人数学审核。

## 不适合实验与证据等级

同一建议协议可返回 ask_missing_condition / explain 而没有计划。回归包括：未知 GS 矩阵要求判收敛、要求运行多元复数 Newton/Python、没有导数界却要求由积分估计证明严格界。没有用伪参数补齐缺条件；执行入口仍拒绝不支持的任务、危险表达式和未确认请求。失败的第二组计算会回滚整次事务。

模型域选择、拒绝实验和 R6.2 有/无上下文比较目前使用 fixture 进行编排验收。三类数值结果来自真实本地 runner；它们不等同真实模型成绩。此前六次真实模型调用的失败保留在 [R6.1 报告](../evaluation/r61-execution-report.md)，本轮没有扩大已用完的调用预算。

## 增加第四类同性质场景

前端只在 `lib/experiment-plans.ts` 增加领域字段、默认草稿和转换；共用 `ExplorationExperiment` 不添加领域表单分支，Explore 页面不复制。后端在 `math_tools/exploration_tasks.py` 扩展有限任务 union，在 `exploration_runner.py` 接现有 runner/存储，追加真实计算及拒绝情况回归。如果已有 reference kind，则沿用；新证据形状需要在 `learning_context.py` 增加局部验证，并补相应客户端类型。无需改 owner/CAS/历史回执或另建注册平台。

例如扩展已有积分领域的求积方法，主要修改原数值 runner、任务 method 枚举、前端方法选项及解析类型，再加数学回归；页面、探索服务和持久化协议不变。自适应 Simpson 的原 runner 不使用 intervals 控制计算，计划校验禁止把它当作有效变化因素。
