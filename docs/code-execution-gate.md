# 学生代码执行：禁用状态与启用门禁

当前 Code Workshop 只做有预算的 AST 静态审阅和学生手工轨迹比较。`code_executed=false`。请求中的 `run_code=true` 被现有严格协议拒绝；数学探索只接受类型化 GS 参数，不能提交 Python 字段。

`test_code_execution_gate.py` 验证进程、网络、无限循环、巨量分配、fork 和动态 exec 文本不会被静态审阅执行。这些测试不证明任何实际执行环境安全。

## 拟定隔离方案

启用执行前采用独立 worker 与隔离基础设施；API 服务不加载或执行学生代码。任务由服务端签名，绑定 owner、assignment、源码摘要、运行策略和截止时间；队列任务不携带会话 JWT、模型密钥或数据库路径。

首选单次短生命周期的 microVM，或经独立安全审查的 gVisor 容器。只读、固定摘要镜像，非 root，禁止特权与宿主挂载，无网络接口，无包安装；仅提供受限临时文件目录。标准容器或 Python 子进程超时本身不足以作为隔离边界。若部署平台无法提供这些条件，继续仅静态审阅。

待测默认预算：单任务 2 秒 CPU、5 秒墙钟、128 MiB 内存、16 个进程/线程、16 MiB 临时空间、64 KiB 输出。输出同时限制字节与结构深度，日志截断记录原始长度；父监控必须杀死整个隔离实例，不只杀一个 Python 进程。以上是待压测的策略起点，尚不是当前运行保证。

每个用户最多一个在途执行；队列、全局并发和每日 CPU 配额分别限制，超额在入队前拒绝。取消、超时和 worker 崩溃不能自动无限重试；同一请求 ID 不能重复计费/运行。队列或 worker 不可用时返回明确失败，不回退到 API 本机执行。

结果保存源码哈希、镜像摘要、策略版本、资源用量、退出原因、截断与清理状态。即使输出正确，也只称“该输入上的受限运行结果”；独立掌握资格仍由既有学习任务与帮助记录决定。

## 必须通过的验收

| 攻击/故障 | 隔离环境必须给出的证据 |
| --- | --- |
| 文件越界、符号链接、环境变量、proc/设备探测 | 无宿主文件、会话、密钥或其他任务可读；输出无泄漏 |
| DNS/HTTP/原始 socket、云元数据地址 | 所有出口被基础设施拒绝，留存网络策略与抓包证据 |
| 无限循环、fork/thread bomb、巨量内存/磁盘/输出 | 对应硬限触发，宿主与其他租户仍可用 |
| 逃逸、ptrace、namespace/mount/capability 探测 | 权限拒绝；由独立审查者验证隔离配置与补丁版本 |
| 取消、断连、worker 崩溃、重复投递 | 整实例终止、临时空间清理、幂等回执，无本机回退 |
| 并发配额、队列淹没、跨用户任务查询 | 先拒绝再消耗资源；其他用户任务不可读取/取消 |
| 来源失效、独立检验帮助锁、身份撤销 | 执行前重新授权；结果不得绕过学习帮助边界 |

开关默认关闭。只有隔离设施到位、上述滥用测试留下可复现结果、负责人和独立安全审核者签署后，才在单独变更中接入执行 API。本轮不创建一个可被误认为已批准的开启配置。
