# 学习设计与当前实现

目标是让学生提出可检查的主张，在反馈后修订，再用独立任务检验理解。系统能记录这个过程；是否带来更好的学习结果仍需学生实验。

## 一条学习路径

1. **提出主张**：在 Chat 输入解题步骤，或从教材、任务、实验和代码工作区带入指定版本的引用。
2. **先作预测**：数值实验记录学生对收敛或变化的预期，避免只观看参考运行。
3. **检查与解释**：有限核验提供局部数学结果；课程片段补充条件，模型选择提示、追问、纠错或实验建议。
4. **修订与对照**：学生修改候选或预览获准参数，保存后产生新版本，原引用仍对应原结果。
5. **独立检验**：在帮助状态允许的任务中重新作答，记录获得帮助、修订和独立完成的区别。

Newton 是路径较完整的实例；线性迭代、积分、教材伴读、讲回与静态代码诊断已有入口，领域覆盖与任务深度并不相同。

## 反馈如何选择

`TeachingDecision` 将学生主张、证据、当前判断和教学动作放在可检查的结构中。系统已有诊断提示、分层帮助和后续动作；反馈是否符合学生的问题，仍需按独立判据审查。

当当前完整学生候选已由确定性核验确认，模型决策不能反向判错；当核验明确失败，模型不能把同一主张标为已支持。局部正确步骤仍可能缺少整题条件，反馈应说明剩余问题，避免将局部结果推广成整个证明正确。

## 哪些记录影响后续教学

近期对话、错因、帮助程度、保存的任务状态及掌握度估计进入后续上下文与提示策略。只有符合来源、范围与资格条件的记录能进入确定性学习证据；参考计算成功不会直接证明学生会做。

掌握度模型的参数是当前启发式设置。它能驱动提示强度，但尚未完成真实学生校准。教学策略比较工具也需要相同题目、资源与帮助条件的观察，不能把不同难度任务的完成率直接比较。

## 完成程度

| 能力 | 当前状态 | 还缺什么 |
| --- | --- | --- |
| Chat 与共享 Workspace | 已接入规范引用、版本和帮助校验 | 系统真人任务验收、移动端与恢复覆盖 |
| 教学决策、实验提案、定向检索 | 已接入主回复路径 | 真实模型对照、独立反馈质量评分 |
| 策略比较 | 已有离线比较与证据准入 | 可比的真实观察与人工评分 |
| 跨会话学习总结 | 已有服务与受限动作接口 | 学生可见的总结入口及跨会话体验验收 |
| 独立掌握与迁移 | 已有帮助记录、自检和任务协议 | 真人独立任务、延迟测验与学习收益证据 |

当前重点应放在正确步骤误判、遗漏条件、unknown 与帮助泄露的失败分析，再决定是否扩大任务或教学策略。

## 对话、材料与入口

普通对话默认不附带来源，也不要求先做实验。首页问题先转入对话草稿，由学生发送；材料、实验和学习任务按需展开。页面主导航、工具入口和会话搜索共用左侧栏，用分隔线区分；手机端收进导航抽屉。

材料工作区复用 Reading 文档与引用接口。登录后可粘贴原文或导入 UTF-8 文本，每次保存形成新文档；直接文本上限为 20,000 字符，选段上限为 6,000 字符。PDF、Word 和 PowerPoint 继续使用已有解析服务。引用先核对来源版本，再进入当前对话；已发送消息保留当时的选段，移除当前引用不会改写历史。用户材料与课程整理材料分别标注来源，未经审核的原文不会显示为教材认证内容。

学习记录入口聚合已有笔记、错因、实验和自检，保留原始页面链接。读取失败会显示对应来源；聚合展示不新增掌握结论。

资料跨页面复用与验收边界见 [R5.1 实施记录](r5.1-materials.md)。侧栏统一搜索保留历史消息内容检索；资料管理直接位于搜索入口下方。

## 从主张到实验与修订

[数学探索](r6.3-shared-experiments.md)将 GS、Newton 与积分的主张、预测、计划、计算和修订归于同一持续探索。学生确认参数后才执行，具体矩阵判据、有限轨迹和积分误差估计分别标注范围。模型建议、学生决定和受控计算保留不同标签。

[私人历史召回](r6.2-personal-decisions.md)在同一用户的新问题中选择有限相关关系和实验，保留原猜测、后来修订与来源版本，并显示为何联想到它。未确认、无关和来源失效的关系不作为依据；旧猜测不补成本题缺失条件。关系接受不改变课程 verified 或独立掌握。有/无上下文的 fixture 对照只验证编排，学习收益和教学质量需要真实模型与真人评价。
